# wtctl: interface

Status: interface 0.1.0-design, 2026-10-30. Written before implementation (architecture §18.1). This document is the single normative source for wtctl's rules; `docs/design.md`, the README and the architecture link to its headings instead of restating them. Where another document differs, this one wins.

wtctl is a Layer 1 primitive: it manages git worktrees, throwaway checkouts and the mapping from repo ids to local clones. It knows nothing about the tools that call it; behavior differs only by explicit arguments. It never runs repository-controlled executable config, never runs `git reset`, `checkout --`, `restore` or `clean` on user files, never runs `git worktree remove` or `git worktree repair` (it deletes worktrees and rewrites their pointers itself), never fetches from the network into a user's clone ([Mirror](#mirror)), never force-pushes (it never pushes at all), and never signals a process it did not start (it signals only the process groups it created for bootstrap steps, hooks, token commands and timed-out git calls).

## Concepts

### Records

wtctl keeps one **record** per object it manages, in its private `state.db`:

| `object_type` | What it is | Created by |
|---|---|---|
| `worktree` | a linked git worktree of a local clone | [`create`](#create) (`owned: true`) or [`adopt`](#adopt) (`owned: false`) |
| `throwaway` | a separate disposable clone, detached at one commit, never trusted | [`create --throwaway`](#throwaway-create-order) |

**Owned and adopted.** A worktree wtctl created is **owned**. A worktree it recorded with `adopt` (one it did not create, possibly the clone's main worktree) is **adopted** (`owned: false`): wtctl records a baseline and checks for it, but only a human can remove it ([Remove order](#remove-order)).

**Holders.** Any worktree record (owned or adopted) carries **holders**, the callers that rely on it: `create --holder <h>` and `adopt --holder <h>` add `h`, and [`forget --holder <h>`](#forget) removes it. While a record has a holder, [`remove`](#remove-order) refuses it (`held`) unless the caller names that holder with `remove --holder <h>`. Throwaways have no holders.

**Record states:**

| State | Meaning | Live? |
|---|---|---|
| `creating` | the record is written, the worktree or throwaway directory is being created ([Create order](#create-order)); [Reconcile](#reconcile) settles one whose creator died | yes |
| `active` | in place and consistent | yes |
| `unlinked` | the directory exists but its git pointers do not match the record; set by [Reconcile](#reconcile) | yes |
| `missing` | the directory is not visible (since `missing_since`), whether or not the clone's admin entry still exists. A reappearing directory returns the record to `active` | yes |
| `clone_missing` | the recorded clone is gone and could not be re-resolved | yes |
| `partial` | a deletion failed part-way; the remaining path is in `last_error` and the clone's admin entry may already be gone ([Partial records](#remove-order)) | yes |
| `gone` | the directory stayed missing and [Reconcile](#reconcile) deleted wtctl's own admin entry (owned records) or gave up on it (adopted records, crashed creates) | no (tombstone) |
| `removed` | removed by [`remove`](#remove) | no (tombstone) |
| `forgotten` | dropped by [`forget`](#forget); nothing on disk was touched | no (tombstone) |

Only [Reconcile](#reconcile) moves a record into `unlinked`, `missing`, `clone_missing` or `gone`; other commands report these states and never set them. What each command does in each state is in [Commands by record state](#commands-by-record-state). An `unlinked`, `missing` or `clone_missing` record needs a human: it leaves that state only through `reconcile` (repair, or `gone` after the grace period), a human [`baseline accept`](#baseline-accept) (which re-attaches a record whose clone moved, reported `moved_clone`) or a human [`forget`](#forget); callers should surface it as needing attention rather than retry `remove`. The refusal for all of these (and for `creating` and `partial` records) is `unlinked` and does not name the state; [`show`](#show) does. Tombstones are kept for `tombstone_days` (default 30) and then deleted by `reconcile`. Selectors and `list` exclude tombstones unless `--state` names them, except as described under Addressing. Ids are never reused.

### Identifiers

| Id | Grammar | Notes |
|---|---|---|
| record id | `^wt-[a-z2-7]{8}$` | allocated before `pre-create` (a vetoed create burns it), or at adopt; never reused |
| repo id | lowercase host, optional `:port` for a non-default port, then `/` and one or more path segments of `[A-Za-z0-9._-]`, no segment equal to `.` or `..` (architecture §16) | e.g. `github.com/org/repo` |
| name | `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` | a worktree's display name and last path component; throwaways have none |
| holder | `^[A-Za-z0-9._:/#@+=,-]{1,64}$` (the label value grammar, at most 64 characters) | `create --holder`, `adopt --holder`, `remove --holder`, `forget --holder` |
| DURATION | `^[1-9][0-9]*[smhdw]$` (seconds, minutes, hours, days, weeks) | `--older-than`, `throwaway.max_age`, `reconcile.missing_grace`, `network_timeout`, `clone_timeout`, `lease_wait` |
| decision id | `^[A-Za-z0-9._:@/-]{1,128}$` | at most 32 per list; a bad `--decision-id` exits 2; hook-returned ids that are invalid, or beyond 32 in total, are dropped with a warning |

**Addressing a record.** Every single-target command takes `<id>` or an absolute path:

- An id may be given as a unique prefix of 4 to 8 characters after `wt-` (the `wt-` itself is optional). Fewer than 4 characters exits 2; no match exits 10; several matches exit 21 with `candidates`. Prefixes never match tombstones. A **full** id also matches a tombstone: `show` prints it; every other command exits 10 with `error.details: {state, removed_at}` ([Commands by record state](#commands-by-record-state)), so an idempotent retry can tell "already removed" from a wrong id: a caller retrying a `remove` or `forget` treats exit 10 whose `details.state` is `removed`, `forgotten` or `gone` as done.
- An absolute path matches the live record whose recorded path equals it; both sides are compared after resolving symlinks (`realpath`). A relative path exits 2.
- Label selectors are accepted only by [`list`](#list) and [`prune`](#prune). No destructive single-target command takes a label selector.

**Names.** `--name` sets the name; otherwise it is derived: from `--branch` (each `/` and each character outside the name grammar becomes `-`, runs of `-` collapse, leading `-`/`.` are dropped), from the adopted path's basename (the same rules, for [`adopt`](#adopt) without `--name`), or, otherwise, the record id's 8 characters. A name is unique per repo among live records: a derived name that collides with a live record's name, or whose rendered path already exists on disk, gets `-2`, `-3`, … appended (after cutting the base so the result fits 64 characters) until both are free; a skipped existing path is named in `warnings`. An explicit `--name` that collides exits 20, `reason: path_exists` (its path would be taken).

### Labels

Labels follow the design guide's multiset rules (section 9) and the grammar of architecture §8.1: a key matches `^[a-z0-9][a-z0-9_.-]{0,63}$`; a value is 0 to 256 characters from `[A-Za-z0-9._:/#@+=,-]`; `--label key=value` splits at the first `=`. A record holds at most 32 label pairs. Adding an identical pair is a no-op. Any violation exits 2. `--json` and hook payloads return labels as a sorted array of unique `key=value` strings (at most 32), as termctl and claude-session do.

### Locations

One visible base directory holds everything a session may need to work in: config key `root` (default `~/wtctl`).

- **Worktrees** are created at `worktree_path` (default `{root}/{host}/{path}/{name}`), where the template variable `{root}` is the repo's worktree root (`repos.<id>.worktree_root`, else `worktree_root`, else `<root>/worktrees`), `{host}` is the repo id's host with `:` replaced by `_`, `{path}` its project path and `{name}` the record's name. `{id}` is also available. `worktree_path` must start with `{root}/` (config validation, exit 2). At create, the worktree root is resolved once with `realpath`, created if missing, checked against its recorded identity ([Create order](#create-order) step 10), and stored in the record as `base_dir`; the recorded path is that resolved root plus the rendered remainder. `{root}` is not the `root` config key: with the defaults it is `~/wtctl/worktrees`, so `worktree_path` never repeats `worktrees/`.
- **Throwaways** live at `<throwaway_root>/<id>/` (default `throwaway_root`: `<root>/throwaway`). The throwaway root and each throwaway directory have mode 0700 and are checked with `lstat` to be directories (not symlinks) owned by the invoking user; the resolved throwaway root is stored in each throwaway record as `base_dir`.
- **Auto-clones** go to `{clone_root}/{host}/{path}` (default `clone_root`: `<root>/clones`).
- **State** (`state.db`, `log.jsonl`, `audit.jsonl`) and the per-clone [mirrors](#mirror) (`mirrors/`) live in `${XDG_STATE_HOME:-~/.local/state}/wtctl/`, never under `root`.

**Path rules** (exit 2):

- A configured `root`, `worktree_root` (global or per repo) or `throwaway_root` must pass claude-session's unsafe-write-target rules (claude-session interface, Path rules): it must not be `$HOME` or an ancestor of it, a directory on `PATH`, `$XDG_CONFIG_HOME`, `$XDG_DATA_HOME` or `$XDG_STATE_HOME` or inside one, or be, or be inside, a `$HOME/.<name>` directory. The defaults pass these rules, so claude-session can run isolated sessions in wtctl's worktrees and throwaways (tested against claude-session's rule list). wtctl implements only the subset that applies to directories it creates, evaluated with its own environment (`$HOME`, hidden home directories, the XDG homes, `PATH`; claude-session's default state root `~/.local/state/claude-session` is inside the XDG state home); claude-session's own check at launch remains authoritative, e.g. for a configured claude-session state root or a different `PATH` in the session environment.
- A rendered path must lie strictly under its root after normalization; a repo id with a `.` or `..` segment is already refused.
- A worktree path must not lie inside any worktree (main or linked) of any clone wtctl knows (configured, recorded, cached discovery hits, and the clone being used), inside wtctl's state dir or throwaway root, and must not contain an existing worktree.
- Paths containing a newline are refused ([Hardened git](#hardened-git)).

## Clone resolution

`locate <repo-id>` and every command that takes `--repo` resolve the repo's local clone in this order; the first hit wins:

1. **Config:** `repos.<id>.clone`. An existing directory must be a git clone whose remote ([`repos.<id>.remote`](#config), default `origin`) URL normalizes to the repo id; otherwise exit 12, `error.code: remote_mismatch` (a config entry is never silently skipped; a clone with no such remote has `details.cause: no_remote`). A configured directory that does not exist is not found: auto-clone (step 4) clones there when enabled, else the command exits 10 with a hint naming [`clone`](#clone). `source: config`.
2. **Recorded clone:** a clone recorded by [`clone`](#clone) or by auto-clone (`state.db`), re-verified like a discovery hit (its remote URL normalizes to the repo id; if not, it is skipped as a source, while the repo's row and its [recorded identity](#clone-resolution) stay). `source: cloned`.
3. **Discovery** (only when `search_roots` is non-empty): wtctl walks each root to `search_depth` levels without following symlinks, considers directories with a `.git` **directory** (linked worktrees, whose `.git` is a file, are skipped), reads the remote URL with hardened git and normalizes it. Hits are cached in `state.db`; a cached hit is re-verified on every use and dropped if it no longer matches. Several matching clones exit 21 with `candidates` (add a config entry to choose). `source: discovered`.
4. **Auto-clone** (only when `auto_clone` is true globally or for the repo): wtctl clones the repo into `repos.<id>.clone` when that is configured, else into its [location](#locations), as described under **Cloning** below. `source: cloned` for the call that cloned. A failure exits 12 (`clone_failed`, or `auth_required` when the host asked for credentials wtctl does not have).

If none applies, the command exits 10 with a hint naming `repos.<id>.clone`, `search_roots` and [`clone`](#clone).

**Anchor identity.** When wtctl first stores a repo's clone in `state.db` (a configured or discovered clone at its first resolution, [`clone`](#clone), auto-clone, [`adopt`](#adopt)), it opens the clone's common git dir through a no-follow chain and records the opened fd's `(st_dev, st_ino)` as `clones.common_id` (first recording, [Mount points](#mount-points)); a clone that wtctl itself clones (auto-clone or `clone`, into a directory it creates) is recorded from that directory, also when the repo's row names an older clone that no longer resolves. [`create`](#create-order) and `adopt` copy it into the record (`common_id`). It is the recorded identity of the common-dir [anchor](#mount-points), kept per repo whatever path the clone later resolves to, and wtctl never re-records it by itself: it changes only through a human, with [`baseline accept`](#baseline-accept) on a record of the clone (the record's `common_id` and the clone's row) or with [`clone`](#clone) run by a human (the clone's row only). A resolution that finds the common dir with a different identity changes nothing stored. `create` and `adopt` then exit 12, `create_failed`, with `details: {cause: "anchor_changed", anchors}` (each [anchor](#baseline-accept) with its recorded and current identity and the current file-system type, mount source and mount point) and the hint "verify the mount, then run `wtctl clone <repo-id>` as a human to re-accept the clone", whether or not the clone has live records; `locate` returns the clone with that warning on stderr. Live records keep their own `common_id`, so each of them refuses (`unlinked`, [Integrity](#integrity)) until a human runs `baseline accept` on it.

**Clone fetch URL.** The one rule for which URL a clone fetches from and is pushed to: the URL of the clone's `repos.<id>.remote` remote (default `origin`), read with hardened git, with userinfo stripped, that normalizes to the repo id and that `git ls-remote --get-url <url>` (hardened) returns unchanged, so no `insteadOf` rewriting applies; otherwise exit 12, `remote_mismatch`. It is stored with the clone in `state.db` (`clones.fetch_url`) and verified again on every resolution; the stored value is replaced when a changed URL passes, and the clone's [mirror](#mirror) is reconfigured to it. [`locate`](#locate)'s `fetch_url`, the URL recorded by [`create`](#create-order) and [`adopt`](#adopt), and the second choice of a [throwaway](#throwaway-create-order)'s `remote` source are this URL.

**Object format.** SHA-256 repositories (`extensions.objectFormat=sha256`) are not supported in v1 ([Platform notes](#platform-notes)): wtctl reads the resolved clone's object format with hardened git; `create`, `create --throwaway` and `adopt` exit 12, `create_failed` with `details.cause: object_format`, and `locate` and `clone` print a warning on stderr.

**Cloning** (auto-clone and [`clone`](#clone)) runs under a per-repo lease keyed by the repo id ([Locking](#audit-and-log)), with hardened git (`clone --template=`, protocol v2, a full clone, credentials as in [Credentials](#credentials), the `clone_timeout` limit). Under the lease wtctl re-checks the destination: one that already holds a clone of this repo (its remote URL normalizes to the repo id and hardened `rev-parse --verify HEAD^{commit}` succeeds) is recorded and reused; any other non-empty destination exits 20, `reason: path_exists`. Otherwise it clones into a sibling temporary directory `<dest>.wtctl-tmp-<random>` and renames it into place; on failure or timeout the temporary directory is deleted. A leftover temporary directory (after a crash) is never reused; [Reconcile](#reconcile) reports it.

**URL normalization.** `https://[userinfo@]host[:port]/path[.git][/]`, `ssh://[user@]host[:port]/path[.git]` and scp-like `user@host:path[.git]` normalize to `host[:port]/path`: the host is lowercased, userinfo, a trailing `.git` and a trailing `/` are dropped, an HTTPS port 443 is dropped, and for SSH URLs the port is ignored. A `file://` URL or a plain path normalizes only when the repo id was configured with `repos.<id>.clone_url` pointing at that same path (tests and mirrors). Any other scheme exits 12, `remote_mismatch`.

### Credentials

wtctl never stores credentials and never uses git credential helpers (global config is isolated, [Hardened git](#hardened-git)). **Private HTTPS repos need `hosts.<host>.token_env`, `hosts.<host>.token_command` or an SSH URL.** For every network git operation (auto-clone, `clone`, throwaway fetches from a remote, [mirror](#mirror) refreshes and base-commit tree fetches, `ls-remote --symref`):

- **HTTPS token.** The host is the host of the URL actually used (a `repos.<id>.clone_url` mirror uses its own host's settings). The token is the value of the variable named by `hosts.<host>.token_env` if it is set and non-empty, else the output of `hosts.<host>.token_command`: an argv list run directly (no shell), with an argument equal to `{host}` replaced by the host, stdin `/dev/null`, a 10-second timeout, the token being its stdout with the trailing newline stripped (e.g. a forge CLI's `auth token`). The command runs in its own process group, which gets SIGKILL on timeout. A non-zero exit, a timeout or empty output gives no token and a warning. The token is passed as a URL-scoped header, `http.<scheme>://<host>/.extraHeader=Authorization: Basic <base64(token_user:token)>`, through `GIT_CONFIG_COUNT` (`hosts.<host>.token_user`, default `x-access-token`), so it is sent only to that host and never across a redirect ([Hardened git](#hardened-git)). The token never appears in argv, in any file, in state, in logs or in output. Without a token the request is anonymous; a 401 exits 12, `auth_required`.
- **SSH.** wtctl passes the caller's `SSH_AUTH_SOCK`; the hardened invocation runs ssh in batch mode (architecture §13.2 rule 10), so host-key and passphrase prompts are never answered: an unknown host key, or a key that needs a passphrase with no agent, fails at once with exit 12, `auth_required`. ssh reads `~/.ssh/config` and `known_hosts` from the home directory in the user's passwd entry, not from `$HOME`.
- Userinfo in a clone's remote URL is stripped before the URL is recorded or used.
- **Token exposure.** Leaving tokens out of bootstrap steps and hooks prevents accidents; it is not a boundary, since a process of the same user can read an ancestor's `/proc/<pid>/environ` ([Residual risks](#residual-risks)). On Linux wtctl calls `prctl(PR_SET_DUMPABLE, 0)` at startup, so a `token_command` token held only in wtctl's memory cannot be read through `/proc/<wtctl pid>/environ` or `mem`. The git child of a network call carries the token in its environment while it runs; wtctl runs no git while bootstrap steps or hooks of the same invocation run. `token_env` values are in the caller's environment anyway, so `token_command` is preferable in shells that launch automation.

## Hardened git

Every git command wtctl runs, on any repository, worktree or throwaway, applies the hardened git invocation of architecture §13.2 rule 10; that recipe is normative there and not restated here. This section lists how wtctl applies it and the parts that are wtctl's own:

- **Git binary and version.** `git_bin` (absolute), else the first absolute `PATH` entry that contains an executable `git` (relative and empty `PATH` entries are ignored), resolved once per invocation; its version must be 2.34 or newer, else exit 12, `git_too_old`. `lsof` ([In-use detection](#in-use-detection)) and the commands of honored filter drivers (below) are resolved the same way. wtctl trusts the caller's `PATH` for these binaries: automation whose `PATH` may contain a directory an agent can write should set `git_bin`. The `PATH` passed to git is the directory of the resolved binary plus `/usr/bin:/bin`, plus the directories of honored filter drivers (below).
- **Protocol allowlist and lazy fetch.** A git command meant to contact a remote sets `GIT_ALLOW_PROTOCOL` to exactly the scheme of the URL in use (`https` or `ssh`, or `file` for a remote configured as a local path in `repos.<id>.clone_url`, as in tests), and runs only in a repository no agent writes (a [mirror](#mirror) or a fresh throwaway) or, for `clone`, into a new directory. Every other git command runs with `GIT_ALLOW_PROTOCOL=none`. Every git command also sets `GIT_NO_LAZY_FETCH=1` (honored by git builds that have it). **No git command ever runs against a user's clone, or any repository an agent may have written, with a `GIT_ALLOW_PROTOCOL` other than `none`.** This is what stops a promisor remote planted in such a repository from running its `uploadpack` command when git needs a missing object (during `status`, `worktree add`, `cat-file`, `rev-list`, `pack-objects` or `diff`): with `none` the lazy fetch git starts fails at the transport check on every supported git, with or without `GIT_NO_LAZY_FETCH` (upstream honors it only from 2.45.1 and some maintenance releases; [live verification](design.md#live-verification)). So objects never move into or out of such a repository by `fetch`, `clone` or `push` run against it: they move as packs that wtctl builds and indexes itself ([Base commits into the clone](#mirror), [Throwaway create order](#throwaway-create-order) step 9).
- **No repository discovery.** Every git command runs either with an explicit `--git-dir` or, when it runs outside any repository (`index-pack` of a transfer pack, `init`, `clone`), with cwd a fresh wtctl-private directory `P` under `${XDG_STATE_HOME:-~/.local/state}/wtctl/tmp/` and `GIT_CEILING_DIRECTORIES` set to the PARENT of `P` (git ignores a ceiling equal to its cwd), so git never discovers an ancestor repository (a home directory kept as a git work tree, for example) and never reads its config.
- **External diff.** The recipe's `-c diff.external=` makes `git diff` fail unless `--no-ext-diff` is given, so every diff-family command wtctl runs passes `--no-ext-diff`; this is required for the command to work at all, not only for safety.
- **Local repositories by plain path.** A configured local remote is addressed by a plain absolute path, never a `file://` URL: git ignores `remote.<name>.*` sections whose name starts with `/`, while a planted `remote.<file-url>.uploadpack` would apply to a `file://` URL.
- **Filters.** Every filter driver named in any config git would read is blanked (`clean`, `smudge`, `process` set empty, `required` false). For worktree checkouts only (`create`, never throwaways), each driver named in `create.allow_filters` is instead given the values of `filter.<name>.*` read from the user's **global** git config (`$XDG_CONFIG_HOME/git/config`, `~/.gitconfig`), passed through `GIT_CONFIG_COUNT` so they override any repository value. A listed driver is honored only when the global config defines `filter.<name>.process` (git-lfs does): a value passed through `GIT_CONFIG_COUNT` overrides only the keys it names, and a repository-planted `process` would otherwise win over a trusted `smudge`, while an empty `process` disables `smudge` too. A listed driver without a global `process`, or not defined globally at all, stays blanked, with a warning. The `PATH` passed to git also contains the directory of each honored driver's command, resolved on the caller's `PATH` at startup (e.g. `/opt/homebrew/bin` for git-lfs on macOS).
- **Driver config check.** An honored driver (git-lfs) reads the clone's config itself. When any driver is honored, `create` reads the repository config and the checkout commit's `.lfsconfig` (with hardened `cat-file`) and refuses with exit 12, `error.code: unsafe_repo_config` (`details.keys` names them) if any key matches `lfs.customtransfer.*`, `lfs.standalonetransferagent`, `lfs.*.standalonetransferagent`, `lfs.extension.*`, `lfs.url`, `lfs.*.access` or `remote.*.lfsurl`. A user who needs those keys drops the driver from `allow_filters`.
- **Recorded fetch URL.** At `create` and `adopt`, wtctl records the [clone fetch URL](#clone-resolution) (userinfo stripped, normalized to the repo id, unchanged by `git ls-remote --get-url`) in the record. Network git for a clone uses only the URL wtctl wrote into the clone's [mirror](#mirror) from the stored clone fetch URL, never a remote name of the clone and never the clone's current config.
- **No network git in the clone.** Reachability and base commits go through wtctl's own [mirror](#mirror); no network fetch ever targets a user's clone, so the clone's `remote.*`, `http.*`, `url.*` and `core.alternateRefsCommand` config never reaches a network call. Refs under `refs/remotes/` are never consulted.
- **Token scoping.** Every repository-config key matching `http.*extraheader` (case-insensitive) is blanked by its exact name through `GIT_CONFIG_COUNT`, like filters, and redirects are not followed (recipe); wtctl's own token header is URL-scoped to the host in use ([Credentials](#credentials)). Network calls run only in a mirror (`--git-dir=<mirror>`), whose config only wtctl writes, in a fresh throwaway with isolated config, or, for `clone`, with no repository and repository discovery disabled (No repository discovery, above).
- **Timeouts.** Every network git call runs in its own process group with `-c http.lowSpeedLimit=1000 -c http.lowSpeedTime=60` (which catches stalled transfers) and a wall-clock limit: `network_timeout` (default `120s`) for mirror refreshes after the first, `ls-remote --symref` and shallow throwaway fetches; `clone_timeout` (default `30m`) for clones, a mirror's first refresh, base-commit tree fetches and `--depth 0` throwaway fetches. On expiry wtctl kills that process group and exits 12 (`fetch_failed` or `clone_failed`) with `details.cause: timeout`.
- **Paths.** A worktree, clone or throwaway path containing a newline is refused: exit 2 for a path given on the command line or in config, exit 12 (`create_failed` or `clone_failed`) for a path rendered from a template. git 2.34's porcelain output is newline-separated.

### Mirror

wtctl keeps one bare, treeless **mirror** per clone, which it alone configures. It is the only repository wtctl's network git fetches into for a clone: the source of the remote's tips ([Reachability](#reachability)) and the relay for base commits the clone lacks. The user's clone is never the target of a network fetch.

- **Location.** `${XDG_STATE_HOME:-~/.local/state}/wtctl/mirrors/<key>.git`, where `<key>` is the first 16 hex digits of the SHA-256 of the realpath of the clone's common git dir: one mirror per clone, a flat name that cannot collide with another repo's mirror or nest inside one, and that differs only in hex digits (safe on case-insensitive file systems). The path is stored with the clone in `state.db` (`clones.mirror_path`), and no two clones store the same path. On first use the directory must not exist or be empty; any other existing directory is never reused, and the refresh fails (`fetch_failed`). Directories are created with mode 0700. A clone that moves gets a new mirror; the old one becomes an orphan (below).
- **Creation.** On first use: `git init --bare --template=` (isolated config), then wtctl writes the config, and only these keys: `core.repositoryformatversion=1`, `extensions.partialClone=origin`, `remote.origin.url=<the stored clone fetch URL>`, `remote.origin.promisor=true`, `remote.origin.partialclonefilter=tree:0`, `gc.auto=0`, `core.logAllRefUpdates=false`. An HTTPS URL is written ending in `.git`, since redirects are not followed and some forges (GitLab) answer a URL without it with a redirect. wtctl rewrites the config whenever the stored [clone fetch URL](#clone-resolution) changes, and before a refresh whenever the file differs from what it wrote.
- **Refresh**, under the per-clone lease, with `--git-dir=<mirror>`, cwd a wtctl-private empty directory, `GIT_ALLOW_PROTOCOL` set to the URL's scheme and [credentials](#credentials) as for any network call: `fetch --no-tags --prune --filter=tree:0 origin '+refs/heads/*:refs/heads/*'` (commits only, no trees or blobs), then `ls-remote --symref <url> HEAD`, also with `--git-dir=<mirror>` (so only the mirror's wtctl-owned config applies; never run outside a repository, where git would discover an ancestor repository of the cwd), after which wtctl points the mirror's `HEAD` at the remote's default branch. The outcome of both is classified as in [Remove order](#remove-order) step 5, including `error:` lines on exit 0; either failure fails the refresh. After a successful refresh the mirror's `refs/heads/*` are the remote's branch tips. Refreshes run in [`create`](#create-order) (step 8), [`remove`](#remove-order) and [`status`](#status) (step 5) and [Reconcile](#reconcile).
- **Pushed check.** Every reachability query runs in the mirror with no network ([Reachability](#reachability)).
- **Base commits into the clone.** When [`create`](#create-order) needs a start commit the clone lacks (a remote-only branch, a remote base, or a `--ref` known only to the mirror), wtctl copies it from the mirror as a pack. Normative properties:
  - The only network transfer is a fetch of tree objects into the mirror.
  - Every git command that reads the clone runs with `GIT_ALLOW_PROTOCOL=none` ([Hardened git](#hardened-git)); no `fetch`, `clone` or `push` runs against the clone, and no git command at all runs in the clone while objects are written into it.
  - The pack is built in the mirror and is **not thin** (it resolves without any object of the clone): resolving a thin pack in the clone would make git lazily fetch the bases it lacks.
  - It is indexed and checked (`--fsck-objects`) outside any repository, before anything is written to the clone.
  - It is installed by plain file writes that create only new files below `<common>/objects/pack/`, opened through a no-follow fd chain from the recorded common dir, whose opened fd must have the record's `common_id`, with every directory and every file it writes on the common dir's device and mount ([Mount points](#mount-points); otherwise `create_failed`); no ref, config, `FETCH_HEAD` or other file of the clone is written.
  - Before `worktree add`, wtctl verifies that the clone now holds every object reachable from the start commit; otherwise `create` fails. Planted refs, alternates or deleted objects in the clone can at most make the transfer fail (objects are content-addressed).

  Implementation recipe (design.md holds the command details); `P` is a fresh wtctl-private 0700 directory under `${XDG_STATE_HOME:-~/.local/state}/wtctl/tmp/`, and every step checks git's exit status:
  1. **Present tips:** the clone's ref tips (`for-each-ref` in the clone) that the mirror has as commits (`cat-file --batch-check` in the mirror). The clone's answer is untrusted; it only shrinks the pack.
  2. **Range and trees:** `rev-list <start> --not <present tips>` in the mirror lists the commits needed; `rev-list --no-walk=unsorted --format=%T` of those commits and of the present tips lists their root trees (never `log` or `rev-parse <x>^{tree}`, which would need the tree objects).
  3. **One network round trip:** `-c fetch.negotiationAlgorithm=noop fetch -q --no-tags --no-write-fetch-head --no-filter origin <tree>...` into the mirror, with the URL's scheme allowed (noop negotiation is required: with the default, a forge may omit objects).
  4. **Pack:** `pack-objects --revs --stdout` in the mirror with `<start> --not <present tips>` on stdin (never `--thin`), written to a file in `P`.
  5. **Index outside any repository:** `index-pack --fsck-objects -o <idx> <pack>` with cwd `P` and `GIT_CEILING_DIRECTORIES` set to the parent of `P` (not `--strict`, which crashes outside a repository on git 2.34; never `--fix-thin`). It prints the pack checksum `<h>`.
  6. **Install:** `pack-<h>.pack`, then `pack-<h>.idx`, each written under a temporary name created with `O_CREAT|O_EXCL|O_NOFOLLOW` in the `objects/pack` directory fd, mode 0444, `fsync`ed and installed under its final name with a no-replace link relative to that fd (`linkat` of the temporary name, then `unlinkat` of it; or `renameat2` with `RENAME_NOREPLACE`); an existing file of the same name is left as it is, and the temporary file is removed (git finds a pack through its `.idx`).
  7. **Verify:** `rev-list --objects --missing=print <start>` in the clone must print no missing object (a line starting with `?`); otherwise exit 12, `create_failed`, and nothing is checked out (the clone lacks objects its tips claimed).
  8. **Check out:** `worktree add` ([Create order](#create-order) step 13).

  With no present tips (an empty or unrelated clone), step 2 covers the whole history, which costs about as much as a full fetch. The pack being non-thin costs at most the size of the range's own objects.
- **Cost.** A mirror's first refresh is a commits-only fetch of every branch (about a quarter to a third of a full fetch); later refreshes transfer only new commits.
- **Orphans.** A mirror whose clone is no longer in `state.db` is reported by [Reconcile](#reconcile) (`stray`, `kind_of: mirror`) and never deleted by wtctl.

### Reachability

Replace refs, grafts and a forged commit-graph can make an unpushed commit look reachable from a remote tip; the recipe disables all three for every wtctl git call (architecture §13.2 rule 10: `GIT_NO_REPLACE_OBJECTS=1`, `GIT_GRAFT_FILE` set to a path that can never exist, `core.useReplaceRefs=false`, `core.commitGraph=false`). Commit objects can also be substituted under their sha by anyone who can write an object store, which no git setting detects. So wtctl's **pushed** test, run in the clone's [mirror](#mirror) with `GIT_ALLOW_PROTOCOL=none` and `GIT_NO_LAZY_FETCH=1` (a lookup of a missing object in a promisor repository would otherwise fetch it lazily), is:

1. **Tips** are the mirror's `refs/heads/*` after a successful [refresh](#mirror) in the same command. Without one (a failed or skipped refresh) there are no tips.
2. **Present and reachable:** `cat-file --batch-check` finds commit `C` in the mirror as a commit, and `merge-base --is-ancestor C <tip>` exits 0 for one of the tips. A missing commit (`missing`, or exit 128) is not pushed. Existence alone never counts: a commit dropped by a force-push stays in the mirror as an object.
3. **Content-verified ancestry:** wtctl finds a parent path from that tip to `C` (`rev-list --parents` in the mirror), reads every commit object on the path with `cat-file --batch`, re-hashes each one (SHA-1 of `commit <length>\0<content>`) and checks that each hop's `parent` line is in the verified content. A hash mismatch, a missing object or a broken hop fails the test with detail `ancestry_unverified`.

`C` is pushed only when steps 2 and 3 pass. This test is used wherever this document says "pushed": the `stash`, `unpushed_head` and `unpushed_branches` [content checks](#content-checks), branch deletion ([Remove order](#remove-order) step 10) and [Reconcile](#reconcile). Without tips, nothing is pushed.

## Create order

The order of [`create`](#create) for a worktree. Each step's failure ends the command; nothing earlier is undone unless the step says so.

1. **Usage checks** (exit 2): `--repo` is required; `--branch` and `--detach` are mutually exclusive; `--branch` passes `git check-ref-format --branch`; `--base` is a branch name (no `refs/` prefix; `origin/main` means a branch named `origin/main`); `--ref` is a full 40-hex sha; labels, `--name`, `--holder`, `--actor` and decision ids match their grammars; `--copy-env` and `--no-bootstrap` together are allowed (copy without steps).
2. **Startup checks:** config valid (exit 2, `config_invalid`); git version (exit 12, `git_too_old`).
3. **Resolve the clone** ([Clone resolution](#clone-resolution); exit 10, 12 or 21). A SHA-256 clone exits 12, `create_failed`, `details.cause: object_format` ([Object format](#clone-resolution)); a common dir whose identity differs from `clones.common_id` exits 12, `create_failed`, `details.cause: anchor_changed` ([Anchor identity](#clone-resolution)).
4. **Allocate the record id.**
5. **Per-clone lease** ([Locking](#audit-and-log)), held through step 13 and released before bootstrap.
6. **Recorded URL:** the [clone fetch URL](#clone-resolution), verified again under the lease ([Hardened git](#hardened-git)); a mismatch exits 12, `remote_mismatch`.
7. **Resolve the name, then the branch** ([Names](#identifiers)):
   - `--detach`: no branch.
   - Otherwise the branch name is `--branch` verbatim, or `branch_prefix` + `branch_template` rendered with the final `{name}`, `{id}` and `{date}` (local date, `YYYYMMDD`). A rendered branch must pass `git check-ref-format --branch` (exit 2).
   - A template-built branch that already exists locally is a collision: the name gets the next suffix (`-2`, …) and the branch is rendered again. With an explicit `--name` the name is never suffixed: a collision of its template-built branch exits 20, `reason: branch_exists` (`details.tip`). Only an explicit `--branch` reuses an existing branch.
8. **Refresh the [mirror](#mirror)** (classified as in [Remove order](#remove-order) step 5, with retries); this also records the remote's default branch as the mirror's `HEAD`. Skipped only when the branch exists locally and no base is needed. Failure exits 12, `fetch_failed` (or `auth_required`). Nothing is written to the clone before `pre-create`.
9. **Classify the branch** (reads only; the branch is created at step 13); the outcome is reported as `branch_action` (`existing`, `track`, `new`, `detached`):
   - **Existing local branch** (explicit `--branch`): checked out as is. `--base`, or a `--ref` other than its tip, exits 20, `reason: branch_exists` (`details.tip`).
   - **Remote-only branch** (among the mirror's `refs/heads/*`, not a local branch): planned as a new local branch at that tip with `--no-track` and an explicit upstream (`branch.<b>.remote` = the record's remote, `branch.<b>.merge` = `refs/heads/<b>`); `created_branch: true`. git's own remote-branch guessing is never used.
   - **New branch:** planned at `--ref` if given, else at the tip of the base, with `--no-track`. The base is `--base`, else `repos.<id>.base`, else the remote's default branch (the mirror's `HEAD`); it resolves to the remote's `refs/heads/<base>` (the mirror's ref) when the remote has it, else to the clone's local `refs/heads/<base>`, never `refs/remotes/`. The record stores the resolved ref name (`base`, `refs/heads/<base>` in both cases) and its sha (`base_sha`). A base that resolves nowhere, or a `--ref` that is a commit neither in the clone nor in the mirror, exits 12, `ref_not_found`.
   - `--detach`: detached at `--ref`, else at the base's tip.
   - A branch checked out in any worktree of the clone (including the main one), or planned by a live `creating` record, is refused: exit 20, `reason: branch_in_use`, with `holder_path` and, if wtctl manages it (also while `creating`), `holder_id`.
10. **Resolve the path** ([Locations](#locations), path rules exit 2). The path must not exist or must be an empty directory, and no live record may hold it; otherwise exit 20, `reason: path_exists` (with `holder_id` when a live record, e.g. a `creating` one from a crashed earlier attempt, holds it). The worktree root is an [anchor](#mount-points) whose identity `state.db` keeps per root (the `anchors` table): a missing root is created (`mkdir`), opened through a no-follow chain, checked to be on its parent's device and mount, and recorded; an existing root without a recorded identity is recorded at this first use (trust on first use, [Mount points](#mount-points) › First recording); otherwise the opened root must have its recorded identity, else exit 12, `create_failed`, `details.cause: anchor_changed`. Then the [driver config check](#hardened-git) (exit 12, `unsafe_repo_config`).

    **Retry after a crash.** When `create --holder <h>` would refuse `branch_in_use` (step 9) or `path_exists` (step 10) and the record named by `holder_id` is `active` and has `h` among its holders, `create` returns that record instead: exit 0 with `"reused": true`, `branch_action` and `bootstrap` null, no hooks, nothing changed (the retry's other flags are not compared). This makes a retry keyed by the holder idempotent once [Reconcile](#reconcile) has reclaimed a crashed create (`adopted_after_crash`); while the record is still `creating`, or when it lacks `h`, the refusal stands, and the caller inspects it with [`show`](#show) `<holder_id>` (`list` has no holder filter). A reclaimed record has `bootstrap.state: "interrupted"` and an empty bootstrap-created set, so removing it automatically will likely refuse `dirty` and need a human.
11. **`pre-create` hooks** ([Hooks](#hooks)): a veto exits 11, an escalation exits 13; nothing outside the mirror has been written.
12. **Record** in state `creating` (planned path, `base_dir`, `common_id` from the clone's row ([Anchor identity](#clone-resolution)), branch, `created_branch`, the recorded URL, the `--holder` if given), and take the per-record lease, held through step 16; the insert and the lease are one `state.db` transaction, so [Reconcile](#reconcile) never sees this record with a free lease while its creator lives.
13. **Add the worktree.** When the start commit is not a commit in the clone, wtctl first copies it from the mirror ([Base commits into the clone](#mirror)); a failure deletes the `creating` record and exits 12: a failed tree fetch with the step 5 classification (`fetch_failed` or `auth_required`), any other failure (building, indexing or installing the pack, or the verification) `create_failed`. Then `git worktree add` (hardened, `GIT_ALLOW_PROTOCOL=none`, with `create.allow_filters`); a new or remote-only branch is created here (`worktree add -b <b> --no-track <start>`), followed by the upstream config writes for `track`. If it fails, a branch this call created is deleted with a compare-and-swap on the sha it was created at and its `branch.<b>` config section is removed, the `creating` record is deleted, and the command exits 12, `error.code: create_failed`. On success wtctl records `admin_dir` (from `git rev-parse --git-dir`), `dir_id` (the worktree directory's `(st_dev, st_ino)`, from a no-follow open), `head_at_create`, the start of the worktree's HEAD reflog and the set of stash entry ids, then releases the per-clone lease.
14. **Bootstrap** ([Bootstrap](#bootstrap)): its steps 1, 2, 4 and 5 run when `--copy-env` was given or steps will run; its step 3 (Steps) runs when the repo has steps, `repos.<id>.bootstrap.auto` is true and `--no-bootstrap` was not given. A failed step keeps the worktree and the record and, after steps 15 and 16, exits 12, `error.code: bootstrap_failed`, with `error.details.record` and `error.details.step`.
15. **Baseline:** the [baseline](#baseline) is recorded now, after bootstrap, so hooks and config that bootstrap installed are part of it.
16. **Activate:** the record becomes `active` (a compare-and-set; losing it exits 1, `internal`, since no other actor changes a record whose lease is held); **`post-create` hooks**, then the output (exit 0, or 12 after a bootstrap failure).

## Throwaway create order

The order of [`create --throwaway`](#create). A throwaway never gets bootstrap, env files, filters, a baseline, a branch or a remote; nothing in it is ever trusted. wtctl itself never runs git in a throwaway after creating it. A caller may run git in a throwaway only with the hardened invocation, and only in a throwaway no untrusted process has run in (e.g. [clean checkout for confirm](#clean-checkout-for-confirm), where `extract` wrote only listed regular files, whose content is untrusted data); no trusted process runs anything in a throwaway an agent has touched.

1. **Usage checks** (exit 2): `--repo` and `--ref` (a full 40-hex sha) are required; `--branch`, `--detach`, `--base`, `--name`, `--holder`, `--copy-env` and `--no-bootstrap` exit 2; `--depth` is an integer ≥ 0 (`0` = full history); `--source local` with a `--depth` other than 0 or 1 exits 2 (a local source copies the full history or depth 1, step 9).
2. **Startup checks** as in [Create order](#create-order).
3. **Allocate the record id.**
4. **Resolve the clone** for every `--source`, never auto-cloning. A resolution failure (exit 10, 12 or 21) ends the command only for `local`; with `auto` or `remote` it means there is no clone (a warning, except for "not found"): `auto` then uses `remote`, and `remote` skips the clone fetch URL in step 8. A SHA-256 clone exits 12, `create_failed`, `details.cause: object_format` ([Object format](#clone-resolution)).
5. **`pre-create` hooks**.
6. **Record** in state `creating` (planned path, `base_dir`, `root_id`, `ref`, `depth`, and `source` as requested, possibly `auto`; `fetch_url` stays null until step 8), under the per-record lease (insert and lease in one `state.db` transaction, as in [Create order](#create-order) step 12). `root_id` is the throwaway root's recorded identity ([Mount points](#mount-points)), which `state.db` keeps per root (the `anchors` table), whether or not any throwaway record exists: a missing root is created (`mkdir`, mode 0700), opened through a no-follow chain, checked to be on its parent's device and mount, and recorded from that fd; an existing root without a recorded identity is recorded at this first use (trust on first use, [Mount points](#mount-points) › First recording); otherwise the opened fd's `(st_dev, st_ino)` must equal the recorded identity, else exit 12, `create_failed`, `details.cause: anchor_changed`. The record copies it as `root_id`.
7. **Create** `<throwaway_root>/<id>/` with mode 0700 ([Locations](#locations)) relative to the root fd (`mkdirat`, then opened no-follow and checked to be on the root's device and mount), record the opened directory's `(st_dev, st_ino)` as the record's `dir_id` before anything is written into it, and run `git init --template=` there with isolated config; write `.git/info/attributes` containing `* -filter`; set `core.logAllRefUpdates=false`.
8. **Choose the source:** `local` uses the resolved clone and requires `cat-file -e <ref>^{commit}` there (else exit 12, `ref_not_found`); `remote` uses, in order, `repos.<id>.clone_url`, the resolved clone's [clone fetch URL](#clone-resolution) (only its URL, never the clone's objects), then `hosts.<host>.clone_url`; `auto` uses `local` when the clone has the commit, else `remote`; with an explicit `--depth` other than 0 or 1, `auto` uses `remote`. `fetch_url` records the URL, or the clone's path for `local`.
9. **Fill** the throwaway with only the commit, by source; then verify `HEAD` equals the ref. Any failure deletes the directory ([Throwaway removal](#throwaway-removal)) and the record, and exits 12 (`fetch_failed`, `ref_not_found`, `auth_required` or, for a failed local pack transfer, `create_failed`).
   - **`remote`:** fetch in the throwaway with the URL's scheme allowed: protocol v2, `--depth <n>` unless 0 (`<n>` is `--depth`, else `throwaway.depth`), `--no-tags`, `--no-recurse-submodules`, `GIT_NO_LAZY_FETCH=1` ([Credentials](#credentials)); then `checkout --detach <ref>`; delete `FETCH_HEAD`.
   - **`local`:** no `fetch` runs against the clone, and every git command that reads it runs with `GIT_ALLOW_PROTOCOL=none` ([Hardened git](#hardened-git)): wtctl builds a pack of the commit in the clone and indexes it in the throwaway, with `--strict` there (so agent-written objects are fsck'ed in a repository whose config only wtctl wrote). The history is the commit's full history, or only the commit itself with `--depth 1` (a shallow throwaway); `throwaway.depth` does not apply to a local source. Recipe: `rev-list --objects <ref>` (`--no-walk` for depth 1) in the clone, written to a file in a private temp dir, its exit status checked (a failed `rev-list` piped into `pack-objects` gives a truncated pack with exit 0); `pack-objects --stdout` in the clone with that file as stdin, exit status checked; for depth 1, `<ref>` written to the throwaway's `.git/shallow` (before indexing, which `--strict` needs); `index-pack --stdin --strict` in the throwaway; `update-ref --no-deref HEAD <ref>`; `read-tree -u --reset HEAD`.
10. **Activate** the record (the `source` used, `fetch_url`, and the `depth` actually used: 0 for a full-history local copy; a compare-and-set, losing it exits 1, `internal`), **`post-create` hooks**, output.

## Bootstrap

Bootstrap prepares a new worktree with the project's own commands. It runs as part of [`create`](#create-order) (step 14) and again on demand with [`bootstrap`](#bootstrap-1). It is refused for throwaways (exit 2) and for adopted records (exit 20, `reason: not_owned`).

1. **Snapshot (before):** two hardened `git status --porcelain=v2 -z` runs: `--untracked-files=all --ignored=no` lists untracked files, each recorded with the SHA-256 of its content; `--untracked-files=normal --ignored=traditional` lists ignored entries (an ignored directory as one entry).
2. **Env files** (only with `--copy-env`): each glob in `repos.<id>.copy_env` is matched against the clone's main worktree (relative paths; `**` allowed). The walk starts from a file descriptor of the main worktree root and opens every component relative to its parent's fd with `O_NOFOLLOW` (directories with `O_DIRECTORY`); it never follows a directory symlink, also not for `**`. Each match must be a regular file (`fstat` on the opened fd) with link count 1; a symlink, a hard-linked file or any other type is skipped with a warning (this is how symlinked and hard-linked sources are refused). It is written to the same relative path in the worktree with the [Extraction rules](#extraction-rules) destination procedure, relative to a file descriptor of the worktree root (each component opened with `O_NOFOLLOW`, missing directories created with `mkdirat` and reopened no-follow, the file created with `O_CREAT|O_EXCL|O_NOFOLLOW` and mode 0600), never overwriting an existing file; a symlinked component, or a path that is tracked in the worktree, is skipped with a warning. With an empty `copy_env`, `--copy-env` warns and copies nothing.
3. **Steps:** each entry of `repos.<id>.bootstrap.steps` runs in order, cwd the worktree root, stdin `/dev/null`, in its own process group. Its environment is the caller's environment minus every variable named by any `hosts.*.token_env` (a `token_command` token is never passed), plus the caller's values of the variables listed in `repos.<id>.bootstrap.pass_env`, plus `bootstrap.env`, plus `WTCTL_ID`, `WTCTL_PATH` and `WTCTL_REPO`. `argv` runs directly; `sh: true` runs `argv[0]` through `sh -c` (then `argv` must have one element). A step exceeding its `timeout` (default 600 seconds) gets SIGTERM and, after 10 seconds, SIGKILL, both sent to the process group wtctl created for it. The first failing step stops the remaining steps; steps 4 and 5 below still run, so the outputs of a failed bootstrap are recorded too.
4. **Snapshot (after):** the entries new since step 1, plus the copied env files, are recorded as **bootstrap-created**: an untracked file by exact path and content hash (it stays exempt only while its content is unchanged), an ignored entry by path (an ignored directory exempts everything below it). Every `.git` file or directory that exists inside a bootstrap-created directory at this point (e.g. a package manager's git dependency) is recorded by path as **`bootstrap_nested`**; only these are exempt from the `nested_repos` [content check](#content-checks). Tracked files changed by bootstrap are reported (`tracked_changes`) but not recorded; they count as dirty at removal.
5. Each step's exit status, duration and the last 4096 bytes of combined output (with the values of `mask_env` variables masked) are stored and returned. Output is untrusted.

**Re-run.** `wtctl bootstrap <id>` re-runs steps 1 to 5 on an owned, `active` worktree. It is a [human-only command](#audit-and-log) (exit 13 without a human actor), because an agent may have changed the worktree since create. It refuses `unlinked`, `in_use`, and `repo_config_changed` on a change in either baseline class (as `baseline check` does, so a re-run never silently re-records agent-made `claude`-class changes) (exit 20). It records as bootstrap-created only new **ignored** entries and the env files this run itself copied (by exact path and hash, even when untracked), never other untracked files; it adds them, and new `bootstrap_nested` entries, to the existing sets, and re-records the [baseline](#baseline) after a successful run.

## Baseline

The **repo-config baseline** detects changes, by anyone, to repository-controlled config that could make a later trusted git operation or Claude session run code (architecture §13.2 rule 10). wtctl records it at [`create`](#create-order) (after bootstrap) and [`adopt`](#adopt), checks it in [`remove`](#remove-order) and [`baseline check`](#baseline-check), and re-records it after a successful bootstrap re-run and with [`baseline accept`](#baseline-accept).

**Items.** Each item has a `class` (`git` or `claude`), a `path`, for config values a `key`, and either `absent` or its type and SHA-256. All reads are no-follow; a symlink is recorded by its target string, never followed. Config files are parsed by wtctl's own parser, never by running git with includes.

Class `git`:

- **Config values** from `<common>/config`, `<common>/config.worktree`, the record's own `<admin_dir>/config.worktree`, and every file reached from them through `include.path` and `includeIf.*.path` (whatever the condition; recursively, depth ≤ 10). Each `section[.subsection].key` is one item (`type: config`, the hash of its values in order). Excluded, because routine git and forge commands write them: `branch.<b>.remote`, `.merge`, `.rebase`, `.pushRemote`, `.description` and `.vscode-merge-base`; `remote.<r>.gh-resolved`, `.fetch`, `.prune` and `.tagOpt`; and keys matching a `baseline.ignore_config_keys` pattern (`section.key`, `section.*.key` or `section.<subsection>.key`; global config only). Every other key counts. Items are keys, not files: an absent config file and one that parses to no keys (empty, or comments only, such as the empty `config.worktree` files claude-session's sandbox creates) contribute nothing and compare equal.
- The hooks directory (`<common>/hooks`) and the effective `core.hooksPath` directory, each as a recursive listing of names, types and content hashes. Every `git`-class directory listing (these and the `modules/**` ones below) is opened through a no-follow fd chain from the recorded common dir and is [anchored](#mount-points) to the common dir. A `core.hooksPath` directory outside the common dir (often a user-wide hooks directory, possibly on another file system) is opened by a no-follow chain from `/` and is its own anchor: its `(st_dev, st_ino)` is stored in its baseline item when the item is recorded and compared with the opened fd before it is listed. A listing whose anchor lacks its recorded identity, whose root or a directory on its chain below the anchor is on another device or (Linux) mount than the anchor, or that holds a mount point (a directory, or a file opened for hashing), is a changed item with detail `mount_point`; a listing that reaches the computation's entry or byte bound ([Bounds](#baseline)) or its [deadline](#mount-points) stops and is a changed item with detail `incomplete`. Both fail safe: such an item never compares equal, so `remove` refuses `repo_config_changed` and `baseline check` refuses. `baseline accept` cannot record an `incomplete` item, or a mount point below its anchor, until the listing fits or the mount is gone; an anchor whose recorded identity differs (after a reboot, for example; [Mount points](#mount-points)) it shows with its mount information and re-records, except on a FUSE file system, which it refuses.
- `<common>/objects/info/alternates`, `<common>/info/exclude` and the effective `core.excludesFile` target.
- Each `<common>/modules/**/config` and `<common>/modules/**/hooks/`, and each `<admin_dir>/modules/**/config` and `<admin_dir>/modules/**/hooks/` (where a linked worktree's submodules keep their git dirs) (listing and hashes).
- The record's own admin entry: `<admin_dir>/commondir` and `gitdir` (other worktrees are covered by their own records' [integrity](#integrity) checks).

Class `claude`: in the worktree, every `.claude/` directory (recursive listing and hashes), every `.mcp.json` and every file matching `CLAUDE*.md`, at any depth. The walk descends into disposable and bootstrap-created directories too (Claude Code loads `CLAUDE.md` from subdirectories it works in); it skips only nested `.git` directories and every `.claude/.cc-writes/` directory, which claude-session's sandbox creates on every sandboxed run (architecture §13.2, residual risk (c)).

**Byte bounds.** One baseline computation (every `git`-class listing and file, the config files and the `claude`-class walk together) hashes at most 64 MiB of one file and at most 256 MiB in total (fixed constants, not configurable), lists at most `remove.nested_scan_limit` entries in total, and each of its walks runs under the walk [deadline](#mount-points). Files are opened with `O_RDONLY|O_NOFOLLOW|O_NONBLOCK` and read from the opened fd; an entry that is neither a regular file nor a directory (a FIFO, socket or device) is recorded by its type only and never read. When a bound or a deadline is reached, the item being read and every item not yet read are changed items with detail `incomplete`, so the computation fails safe instead of waiting on an endless file or tree. Every file the baseline reads below the common dir, in a `git`-class listing or in the `claude`-class walk is opened through the anchored no-follow chain and must have the anchor's device and (Linux) mount on its opened fd, else its item (for a config file, an item with the file's `path` and `key` null) is changed with detail `mount_point`. In the `claude`-class walk, a directory on another device or mount is not descended into and is reported as a changed `claude` item with its path and detail `mount_point`. Config files reached through `include.path` outside the common dir and the `core.excludesFile` target are bounded the same way but not anchored.

The **digest** is the SHA-256 of the sorted item list of both classes. `remove` refuses (`repo_config_changed`) only when a `git`-class item changed, and reports `claude`-class changes as a warning (`checks.baseline.status: "warn"`), since Claude config cannot run during wtctl's hardened removal. `baseline check` refuses on a change in either class. Changes are reported as items (`class`, `path`, `key`, `before`, `after`), never with file contents.

## Removal checks

### Integrity

Before running any git command in a worktree, wtctl verifies, by reading files without following links: the record's path equals the recorded path; for an owned record it lies under the recorded `base_dir`, and no component below it is a symlink (each opened with `O_NOFOLLOW` from a file descriptor of `base_dir`; symlinks in its own ancestry were resolved at create), nor on another device or mount than `base_dir` ([Mount points](#mount-points)); `<path>/.git` is a file whose `gitdir:` line names exactly the recorded `admin_dir`; that directory's `gitdir` file names `<path>/.git`; its `commondir` resolves to the recorded common dir; and `git rev-parse --git-common-dir` (hardened, explicit `--git-dir`) returns the same. The admin entry is opened from a file descriptor of the recorded common dir (a realpath, opened no-follow, whose `(st_dev, st_ino)` must equal the recorded `common_id`), one component at a time with `O_NOFOLLOW`, and it and every directory on that chain must be on the common dir's device and mount ([Mount points](#mount-points)). Any mismatch is the refusal `unlinked`. For an adopted main worktree the checks are that `<path>/.git` is the recorded common dir, with the recorded `common_id`. The worktree directory's `(st_dev, st_ino)` is compared with the recorded `dir_id` where wtctl deletes or rewrites something by path ([Remove order](#remove-order) step 9, [Reconcile](#reconcile)).

### Content checks

All of the following are evaluated, and every result is reported in `checks` (check object: `status` and `details`, `schemas/defs.json#/$defs/checks`):

- **`tracked`:** any staged or unstaged change to a tracked file, or a conflict (`status --porcelain=v2 -z --untracked-files=all --ignored=no --ignore-submodules=all`; detail `changed`). Every tracked file is compared by **content**: the worktree's index is agent-writable, and git's status trusts an index entry whose stat data matches the file, so forged stat data would hide an edit. wtctl therefore never runs this status against the worktree's own index: it builds a private index (`GIT_INDEX_FILE` in a wtctl-private temp file) from `ls-files -s -z` with `update-index -z --index-info`, which carries no stat data, and runs status against that, with `-c core.untrackedCache=false -c core.checkStat=default -c core.trustctime=true -c core.ignoreStat=false`. The cost is one hash of every tracked file per check (in `remove`, again at its step 9 re-check, and in `status`). git's status skips index entries flagged assume-unchanged or skip-worktree, so wtctl also runs `ls-files -v -z`: every entry tagged with a lowercase letter (assume-unchanged) or `S`/`s` (skip-worktree) fails the check with detail `hidden_changes` and its path, whether or not its file was edited. A sparse checkout sets skip-worktree on every path outside its cone, so a sparse-checkout worktree always fails `tracked` and needs a human `--force` to remove in v1 ([Residual risks](#residual-risks)).
- **`untracked`:** any untracked, non-ignored file (from the same `--untracked-files=all` run, so against the private index and without the untracked cache, which an agent could forge too) that is not bootstrap-created with unchanged content ([Bootstrap](#bootstrap) step 4).
- **`ignored`:** any ignored path (from `--untracked-files=normal --ignored=traditional`, also against the private index and without the untracked cache) that is neither bootstrap-created nor matched by `remove.disposable` (per repo, else global). Disposable patterns use gitignore syntax: a trailing `/` matches directories only, a pattern without `/` matches at any depth.
- **`nested_repos`:** any `.git` file or directory anywhere below the worktree root, except the worktree's own `.git` and the recorded `bootstrap_nested` entries ([Bootstrap](#bootstrap) step 4), found by a no-follow walk of the whole tree that descends into ignored, disposable and bootstrap-created directories and stops descending at a found `.git`. A walk exceeding `remove.nested_scan_limit` entries (default 2000000) or its [deadline](#mount-points) fails the check with detail `incomplete`; it never passes. **Mount points:** the walk never crosses a mount point ([Mount points](#mount-points)); a mount point anywhere below the worktree root (a directory whose device or mount id differs from the root's, such as a FUSE file system an agent mounted in `node_modules/`) fails the check with detail `mount_point` and its path, whether or not the directory is ignored, disposable or bootstrap-created, so `remove` refuses `dirty` before deleting anything. **Submodules** (a v1 limitation; no recursion): a `.git` file of an initialized submodule (its path is listed in `.gitmodules` at `HEAD`, read with hardened git, and it points under `<admin_dir>/modules/` or `<common>/modules/`) fails the check with detail `submodule`, since removal deletes the submodule's git dir under the admin entry together with any unpushed submodule commits. Submodule checkouts are never bootstrap-created (they are tracked gitlinks), so a worktree with initialized submodules needs a human `--force` to remove in v1 ([Residual risks](#residual-risks)). Any other nested `.git` fails with detail `nested_repo`.
- **`stash`:** a `refs/stash` entry E counts if its object id is not in the set recorded at create or adopt, its first parent equals `HEAD` or is an ancestor of `HEAD`, and its first parent is not [pushed](#reachability).
- **`unpushed_head`:** `HEAD` is not [pushed](#reachability) and is not equal to `--merged-head` (detail `not_reachable` or `ancestry_unverified`).
- **`unpushed_branches`:** any local branch whose tip appears in the worktree's HEAD reflog since the recorded start, differs from `HEAD`, and is not [pushed](#reachability) (side branches committed in this worktree). The **reflog start** is recorded at create or adopt as that moment's timestamp plus the new sha of the reflog's last entry (the **start entry**). An entry belongs to this worktree when its timestamp is at or after the recorded start, or when it comes after the start entry in the file (positional; used while the start entry, matched by its sha at a timestamp at or before the start, is still present), so an entry backdated with `GIT_COMMITTER_DATE` is still attributed while the start entry exists. Fail-safe: if the reflog is missing or unreadable, or neither anchor is usable (no entry at or before the start and no start entry: emptied by `reflog expire`, which keeps the file, or expired by gc after `gc.reflogExpire`, 90 days by default), the check fails with detail `reflog_unavailable`. So a worktree older than the reflog expiry needs a human `--force` for this check. A repository-level `core.logAllRefUpdates=false`, which stops new reflog entries, is a `git`-class [baseline](#baseline) change.

`tracked`, `untracked`, `ignored`, `nested_repos` and `stash` make the refusal `dirty`; `unpushed_head` and `unpushed_branches` make it `unpushed`. Only a human `--force` overrides them.

### In-use detection

A worktree or throwaway is **in use** when a process of the invoking user has its cwd or an open file inside its directory.

- **Linux and WSL.** wtctl collects the `(st_dev, st_ino)` of every **directory** inside the target by a no-follow walk of directories only that never crosses a [mount point](#mount-points) and stops after `remove.nested_scan_limit` entries or at its [deadline](#mount-points) (with a warning; the path matches below still cover the whole target, only the device-and-inode match of cwds is then partial). A process is in use when `stat("/proc/<pid>/cwd")` yields a `(st_dev, st_ino)` in that set, or when the `readlink` target of its cwd or of any `/proc/<pid>/fd/<n>` (with a trailing `(deleted)` marker and the space before it removed) has the target path as a path-component prefix. Matching cwds by device and inode finds a sandboxed process that sees the directory under another path (a bind mount in a mount namespace); open files are matched by path only, since Claude Code's sandbox binds the worktree at the same path (spike E3).
- **macOS.** `lsof -a -d cwd -Fpcn -u <uid>` and `lsof -Fpcn +D <dir>`, path matching only.
- Processes of other users and unreadable entries are skipped and counted (`uninspected`). On WSL, Windows processes (e.g. an editor running on Windows with the directory open) are not visible. When no scanner is available (no `/proc` and no `lsof`), the check is skipped with a warning (`checks.in_use.status: "unavailable"`).
- **Excluded:** wtctl's own process, its children and its ancestor chain (a parent-PID walk to PID 1, each verified by PID and start time). Excluded ancestors whose cwd is inside the target are listed in `warnings`. So a caller may run `wtctl remove` from a shell whose cwd is the worktree, but no other process of the caller's may keep a cwd or open file inside it. Callers that run commands in a throwaway should run them in their own process group and kill that group before `remove`.

The refusal lists `pid`, the command name and the matching path for each process (`processes`; non-printable bytes in `path` are escaped as `\xNN`; both are untrusted). wtctl never signals them.

### Mount points

`O_NOFOLLOW` stops symlinks, not mount points: opening a directory or file on which a file system is mounted yields the mounted root. An agent can mount a file system on a directory or a file it owns without privileges (FUSE through the setuid `fusermount3`), for example a pass-through view of another directory, so **no walk wtctl does ever crosses a mount point, or starts on one**. A mount placed on the walk's own root (a FUSE file system mounted on `<common>/worktrees/<n>`) is not a crossing as seen from the root, and a mount placed on the anchor itself or on one of its ancestors (on the common dir, or on the throwaway root) is not a crossing as seen from the anchor, so every walk is checked against an **anchor** whose identity wtctl recorded when it first recorded the location, never one read at operation time.

- **Anchors.** Every fd-based walk has one, and each anchor has a recorded identity, the `(st_dev, st_ino)` of its directory:
  - the recorded common dir, identity `common_id` (in the record and in `clones.common_id`, [Anchor identity](#clone-resolution)): admin-entry deletion ([Remove order](#remove-order) step 9, [Partial records](#remove-order), [Reconcile](#reconcile) › Missing), the admin-entry pointer rewrites ([Reconcile](#reconcile) › Unlinked), the `objects/pack` install ([Mirror](#mirror)), and the [baseline](#baseline)'s `git`-class directory listings and files below the common dir (`<common>/hooks`, the effective `core.hooksPath` directory when it lies inside the common dir, `<common>/modules/**`, `<admin_dir>/modules/**`, the config files);
  - a `core.hooksPath` directory outside the common dir: the directory itself, with the identity stored in its baseline item ([Baseline](#baseline)); the no-follow chain from `/` to it is not compared (it may legitimately cross mounts);
  - the worktree directory, identity `dir_id`, plus, for an owned worktree, the recorded root `base_dir` (its identity kept per root in the `anchors` table and checked at [create](#create-order) step 10), whose chain down to the worktree directory must stay on one device and mount: worktree deletion (step 9 and [Partial records](#remove-order)), the `nested_repos` walk, the baseline `claude`-class walk and the [in-use](#in-use-detection) directory walk of a worktree ([Integrity](#integrity) checks the chain before any of them). An adopted record has no `base_dir`; its worktree directory, verified by `dir_id`, is the anchor, and the chain from `/` to it is not compared (it may legitimately cross mounts);
  - the throwaway root, identity `root_id` (kept per root in the `anchors` table and copied into each throwaway record), plus the throwaway directory, identity `dir_id`: [throwaway removal](#throwaway-removal) (also of a `partial` one and of a crashed create, [Reconcile](#reconcile)), the in-use walk of a throwaway, the [extraction](#extraction-rules) source, and the extraction destination when it lies inside a throwaway (the [clean checkout](#clean-checkout-for-confirm));
  - locations wtctl never recorded, whose anchor is opened at operation time: a `--dest` outside any throwaway (it only receives listed files, [Extraction rules](#extraction-rules)) and the clone's main worktree root for the [bootstrap](#bootstrap) `copy_env` source walk (only read).
- **Rule.** wtctl opens the anchor through a no-follow chain (`openat` with `O_NOFOLLOW|O_DIRECTORY`, one component at a time) and compares the opened fd's `(st_dev, st_ino)` (`fstat`) with the **recorded** identity before anything else. On Linux, before opening the anchor, wtctl also reads `/proc/self/mountinfo` and treats every mount point at or below the anchor's path as a mismatch without opening it: the anchor itself or a directory on the chain refuses as **At the anchor** below, one inside the tree is a mount point as **Inside the tree** below (so an anchor directory must not itself be a mount point; [Residual risks](#residual-risks)). A FUSE file system cannot present the underlying file system's `st_dev`, so a mount on the anchor or on any of its ancestors fails this comparison. wtctl then reads the anchor fd's mount id on Linux (the `mnt_id` line of `/proc/self/fdinfo/<fd>`, which also tells apart a bind mount of the same file system; it is not recorded, since it changes across reboots). Every directory opened on the no-follow chain from the anchor to the walk's root, the root itself (and its recorded `dir_id`, where it has one), every directory the walk opens inside it and every regular file it opens are compared by `fstat` of the **opened fd** (never a `stat` by name before opening, which leaves a window) with the anchor's `st_dev` and mount id. macOS compares `st_dev` only.
- **At the anchor, at the root or on the chain**, a mismatch means the recorded location is not what it was, and the operation refuses before deleting, writing or reading anything there: for a worktree or an admin entry, exit 20, `reason: unlinked` (the record stays as it was; in [Reconcile](#reconcile) the entry is kept and the record reported `unlinked`); for a throwaway, `remove` exits 20, `reason: unlinked` and the record stays; for extraction, a source throwaway that fails is `not_found` and a `--dest` chain mismatch is `dest_conflict`; for the `objects/pack` install, `create_failed`; for the `copy_env` walk, nothing is copied (a warning); for a baseline listing or file, the item counts as changed with detail `mount_point` (refusal `repo_config_changed`, [Baseline](#baseline)).
- **Inside the tree**, a directory or regular file whose opened fd mismatches is a mount point; it is closed and never descended into, read or deleted from:
  - **Content checks** report a mount point below a worktree root as `nested_repos` detail `mount_point` (refusal `dirty`), so an unforced `remove` refuses before deleting anything.
  - **Deletion** (also under `--force`, also of a throwaway, a `partial` record or an admin entry) skips a mount point and everything below it (a file system mounted on a file cannot be unlinked either); the directory containing it cannot then be removed, so the record becomes `partial`, with the mount point's path among `details.remaining`. A human unmounts it before finishing the record.
  - **Extraction** treats a source path that crosses a mount point, or a source file on another mount, as `not_found`, and a destination component that is a mount point as `dest_conflict`.
  - **Baseline** listings and the `claude`-class walk report a mount point inside them (a directory, or a file opened for hashing) as a changed item with detail `mount_point`.
  - **Other walks** (in use, `copy_env`) skip a mount point, with a warning.
- **Bounds.** The in-use walk is bounded by `remove.nested_scan_limit` entries, and the `nested_repos` walk fails `incomplete` beyond it; one baseline computation lists at most `remove.nested_scan_limit` entries and reads at most 64 MiB of one file and 256 MiB in total ([Byte bounds](#baseline)).
- **Deadlines.** Every open a walk makes is non-blocking (files `O_RDONLY|O_NOFOLLOW|O_NONBLOCK`, directories `O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_NONBLOCK`), and an entry that is neither a regular file nor a directory (a FIFO, socket or device) is recorded by its type only and never opened for reading. Each anchored walk, from the anchor open to its last entry, runs in a child process with a hard deadline, fixed at 60 seconds per walk and 300 seconds for all walks of one `remove` together (baseline, content checks, in-use walk, re-check and deletion); on expiry wtctl kills the child with SIGKILL by the exact PID it started (SIGKILL also ends a wait inside a FUSE request). An expired deadline fails safe, as a bound does: an anchor open or chain check that did not finish is a mismatch (**At the anchor** below; `unlinked` for worktrees, admin entries and throwaways); an unfinished baseline item is changed with detail `incomplete`; the `nested_repos` walk fails with detail `incomplete` (refusal `dirty`); the in-use directory walk ends with a warning, as at its entry bound; an unfinished deletion leaves the record `partial` (a later `remove` continues); extraction writes nothing (`extract_invalid`, unread paths `limit_exceeded`) unless writing had started (`io_error`); the `objects/pack` install is `create_failed`; the `copy_env` walk copies nothing more, with a warning.
- **Recorded identities after a reboot.** Some file systems (network and FUSE-backed ones, for example) may present a different `st_dev` after a reboot or remount. Every anchored operation on such a location then refuses (`unlinked`, `create_failed`, or a baseline item with detail `mount_point`), which fails safe. wtctl never re-records an identity by itself; only a human does, after looking at the mount information wtctl shows: [`baseline accept`](#baseline-accept) on a worktree record (its anchors, including the clone's row), and [`clone`](#clone) for a clone's row. A throwaway, which has no baseline, is deleted by hand, after which [Reconcile](#reconcile) marks its record `gone`; a throwaway root, or a worktree root no record can re-accept, is re-recorded only when the human removes it and wtctl creates it again. Neither path accepts an anchor on a FUSE file system. There is no other command or flag for this.
- **First recording.** Each identity is recorded once: a clone's `common_id` when wtctl first stores the repo's clone ([Anchor identity](#clone-resolution)), a worktree or throwaway root's when wtctl first needs it (the `anchors` table), a worktree's or throwaway's `dir_id` right after wtctl creates the directory (or at `adopt`). Where wtctl created the directory itself (`mkdir`, checked on its parent's device and mount), the identity is its own; where the location already existed (a root created by hand, a configured or discovered clone, an adopted worktree), first recording is trust on first use: a mount already in place then becomes part of the recorded identity, so a location that was already mounted over when wtctl first recorded it is not protected by this rule.

## Remove order

The order of [`remove`](#remove) for a worktree. [`status`](#status) runs steps 1 to 6 without the per-record lease and reports what `remove` would do, changing nothing except the [mirror](#mirror) refresh.

1. **Resolve** the record ([Identifiers](#identifiers)) and take the per-record lease. A record that is not `active` is handled as in [Commands by record state](#commands-by-record-state); a `partial` record follows [Partial records](#remove-order) below. Removing an adopted record is a [human-only command](#audit-and-log): without a human actor it exits 13, `confirmation_required` (`status` reports `human_required: true`). An adopted main worktree is always refused: exit 20, `reason: main_worktree`.
2. **[Integrity](#integrity)** → exit 20, `reason: unlinked` (run [`reconcile`](#reconcile)). Then the **lock**: if `<admin_dir>/locked` exists → exit 20, `reason: locked`, with `details.lock_reason` (the file's content, untrusted); `checks.locked` reports it. Nothing overrides it; wtctl checks the lock itself again just before deleting (step 9).
3. **[Baseline](#baseline)** → a `git`-class change exits 20, `reason: repo_config_changed`, with the changed items; `claude`-class changes are a warning. `--force` does not override it; a human runs `baseline accept` after inspecting the change.
4. **[In use](#in-use-detection)** → exit 20, `reason: in_use`. Nothing overrides it. Then the **holders** (a local check, so it comes before the fetch): a holder other than the one named by `--holder` → exit 20, `reason: held`, with `details.holders` (every holder); `checks.held` reports it. Only a human `--force` overrides it, and then the later steps run.
5. **Refresh the [mirror](#mirror)** under the per-clone lease; its `refs/heads/*` are then the tips for [Reachability](#reachability). The outcome of each git call of the refresh (the fetch and `ls-remote --symref`) is classified by git's exit status and stderr (the recipe sets `LC_ALL=C`):
   - exit 1 with `cannot lock ref` or `unable to update local ref` in stderr: ref-lock contention, retried up to `remove.fetch_retries` times, 1 second apart; contention that outlasts the retries, and any other exit 1, is `fetch_failed`;
   - exit 128: a transport failure, `auth_required` when stderr contains `could not read Username`, `terminal prompts disabled`, `Authentication failed`, `Permission denied (publickey` or `Host key verification failed`, else `fetch_failed`;
   - the [timeout](#hardened-git) kill: `fetch_failed` with `details.cause: timeout`;
   - exit 0 with any stderr line starting with `error:`: `fetch_failed` with `details.cause: prune_incomplete` (a `--prune` that could not delete a ref exits 0 and leaves the stale ref);
   - exit 0 otherwise: success. Any other exit status is `fetch_failed`.

   Failure exits 12 with that code. With a human `--force` either failure is a warning (`checks.fetch` fails and is overridden): nothing is [pushed](#reachability), so the unpushed checks fail and step 10 keeps the branch.
6. **[Content checks](#content-checks)** → exit 20 with `reason: dirty` if any dirty check failed, else `reason: unpushed`, unless a human `--force` overrides them. wtctl remembers `HEAD` and every failing detail (path, stash entry, branch) for step 9.
7. **Confirmation:** from a TTY without `--yes`, wtctl shows the record, the check results and what `--force` overrides, and asks. Without a TTY and without `--yes`, it exits 13 (`error.code: confirmation_required`) having changed nothing. `--yes` skips only this prompt; it never overrides a refusal.
8. **`pre-remove` hooks**: a veto exits 11, an escalation exits 13 (`error.code: escalated`); `--override-escalation` (human only) counts escalations as allow.
9. **Re-check and delete**, under the per-clone lease: re-run steps 2 (including the lock), 3 and 4 (in use and holders) and the `tracked`, `untracked`, `ignored` and `stash` checks (`nested_repos` and `unpushed_branches` are not re-run; [Residual risks](#residual-risks)), and compare `HEAD` with the `HEAD` seen at step 6. A moved `HEAD` refuses `unpushed` (`unpushed_head` detail `head_moved`); any failure that is new since step 6 (a check that passed then, or a failing detail that was not reported then) refuses with its normal reason, **even under `--force`**: the human confirmed the state shown at step 7, not a later one. Then wtctl deletes the worktree itself, fd-based; it never runs `git worktree remove`, whose path-based recursion follows a directory swapped for a symlink mid-walk:
   - **Open:** each component from a file descriptor of the recorded `base_dir` (owned) or of `/` (adopted) down to the recorded path is opened with `O_NOFOLLOW|O_DIRECTORY`, every directory on that chain and the worktree directory must be on `base_dir`'s device and mount (owned records; [Mount points](#mount-points)), and the worktree directory's `(st_dev, st_ino)` must equal the recorded `dir_id`; otherwise exit 20, `reason: unlinked`, nothing deleted. Then `<admin_dir>/locked` is checked once more (through the no-follow fd chain from the common dir): present → exit 20, `reason: locked`, nothing deleted.
   - **Tree:** deleted through directory fds exactly as in [Throwaway removal](#throwaway-removal) (symlinks removed as links and never followed, [mount points](#mount-points) never crossed, `u+w` added to directories owned by the invoking user); the worktree's own `.git` file is deleted after every other entry, then the directory itself relative to its parent's fd.
   - **Admin entry:** before the tree is deleted, wtctl opens `<common>/worktrees/<n>` through the no-follow fd chain from the recorded common dir, whose opened fd must have the recorded `common_id`, and checks that `worktrees` and the entry are on the common dir's device and mount (the [anchor](#mount-points)); a mismatch (for example a file system mounted on the entry, on the common dir or on one of its ancestors) exits 20, `reason: unlinked`, with nothing deleted. After the tree, it deletes the entry fd-based from that fd (never crossing a [mount point](#mount-points) inside it), after verifying through the fd that its name matches `admin_dir` and that its `gitdir` file names `<recorded path>/.git`; an entry naming another path is left and reported in `warnings`.
   - **Failure:** an entry that cannot be deleted leaves the record `partial` (`last_error` names the remaining path), and the command exits 1, `error.code: partial`, with `details.remaining_path` and `details.remaining` (the entries left, at most 100). A human finishes it ([Partial records](#remove-order)).
10. **Branch:** if `created_branch` is true, `remove.delete_branch` is true, `--keep-branch` was not given and the branch tip is [pushed](#reachability) or equals `--merged-head`, wtctl deletes it with `update-ref -d refs/heads/<b> <verified tip>` (never the zero sha) and removes the `branch.<b>` config section. Otherwise it reports `branch_kept_reason` (`not_created`, `disabled`, `keep_branch`, `unpushed`, `checked_out_elsewhere`).
11. **Record** → `removed` (a compare-and-set on the state, [Locking](#audit-and-log)); append the [audit](#audit-and-log) records; **`post-remove` hooks**; output (exit 0).

**Refusal precedence.** When several refusals apply, `reason` is the first of: `main_worktree`, `unlinked`, `locked`, `repo_config_changed`, `in_use`, `held`, `dirty`, `unpushed`. Steps 2 to 4 stop at their refusal (`held` only without a human `--force`, which overrides it), so a `held` record is refused before the fetch, as `status` reports it; `status` and a refusal at step 6 report all content checks.

**`--force`** (a [human-only flag](#audit-and-log): exit 2 without a human actor) overrides only `held`, `dirty`, `unpushed` and a fetch failure at step 5 (`fetch_failed` or `auth_required`), as they were at step 6 (step 9). A forced removal keeps an unpushed branch (`branch_kept_reason: unpushed`) so its commits stay reachable in the clone; `overridden` in the output, the `pre-remove` payload and the audit record lists the overridden checks.

**One remote.** Only `repos.<id>.remote` is fetched. A branch pushed only to another remote (a personal fork) looks unpushed: callers pass `--merged-head`, or the user sets `repos.<id>.remote` to the remote they push to.

**Partial records.** Finishing a `partial` worktree is human-only (exit 13 without a human actor); finishing a `partial` throwaway is not ([Throwaway removal](#throwaway-removal)). If the worktree's `.git` pointer and its admin entry are both still intact (the deletion stopped before reaching them; [integrity](#integrity) passes), `remove` runs as a normal removal from step 2, content checks included. Otherwise it does not require the admin entry and runs no git and no content checks: it verifies that the remaining path is exactly the recorded path, compared component by component from `/` with each component opened `O_NOFOLLOW` (under the recorded `base_dir` for an owned record, each component below it on `base_dir`'s device and mount; for an adopted record, which has none, the recorded path alone), and that its `(st_dev, st_ino)` equals `dir_id` (a mismatch exits 20, `reason: unlinked`), checks [in use](#in-use-detection) (exit 20, `reason: in_use`), then shows the remaining path with its entry count and at most 100 of its entries and asks for confirmation as in step 7 (a TTY prompt, or `--yes` with a human actor; without either, exit 13), runs the `pre-remove` hooks as in step 8 (the payload's record has `state: partial`; its `checks` report the content checks `skipped`), deletes the path fd-based, adding `u+w` to owned directories as for throwaways ([Throwaway removal](#throwaway-removal)), and, if the record's admin entry still exists and its `gitdir` file names `<recorded path>/.git`, removes that entry fd-based (as in step 9, anchored to the common dir: a common dir without its recorded `common_id`, or an entry or chain directory on another device or mount, refuses `unlinked` before anything is deleted, and the record stays `partial`) (an entry naming another path is left and reported in `warnings`). Files written there after the failed removal are deleted unchecked; the confirmation is the human's look at them. The record becomes `removed`. A deletion that fails again keeps it `partial` (exit 1, `partial`). [`status`](#status) on such a record reports `human_required: true`, `would_remove: true` (`false` with `reason: in_use` when in use), the content checks `skipped` and the remaining path in `warnings`; on a `partial` throwaway it runs the in-use check only, with the same `would_remove`.

## Throwaway removal

[`remove`](#remove) of a throwaway, also of a `partial` one (finishing it is not human-only): no confirmation, no baseline and no content checks, and no git command. wtctl takes the per-record lease, checks [in use](#in-use-detection) (exit 20, `reason: in_use`), fires `pre-remove`, verifies that the throwaway root, opened no-follow, has the recorded `root_id`, and that the directory is exactly `<base_dir>/<id>/`, opened no-follow from the root fd, on the root's device and mount and with the recorded `dir_id` (else exit 20, `reason: unlinked`, nothing deleted; [Mount points](#mount-points)), and deletes it fd-based: each directory opened with `O_NOFOLLOW|O_DIRECTORY`; when `fstat` shows a directory owned by the invoking user without write permission, it is `fchmod`ed to add `u+w` first (read-only test fixtures); entries removed with `unlinkat`/`rmdir` relative to the directory fd; symlinks removed as links and never followed; a directory whose `fstat` (of the opened fd) shows a different `st_dev` or, on Linux, a different mount id than the throwaway root is a [mount point](#mount-points), never descended into. Then it marks the record `removed`, logs it (no audit record) and fires `post-remove`. A directory that no longer exists marks the record `gone` (exit 0, with a warning). Entries it cannot delete (e.g. root-owned files a container left, or a mount point, which is skipped with everything below it) mark the record `partial` and exit 1, `error.code: partial`, with `details.remaining_path` and `details.remaining` (the entries left, at most 100); a later `remove` or [`prune`](#prune) retries. `--force`, `--merged-head`, `--keep-branch` and `--holder` exit 2 for throwaways.

## Extraction rules

[`extract`](#extract) copies agent-written files out of a throwaway into a destination directory, and deletes listed files there, without ever following a link or running git. These are the normative rules for review-respond's confirm (architecture §20).

**Lists.** `--files-from <file>` and `--delete-from <file>` (either may be `-` for stdin, not both) hold relative paths separated by NUL, or by newlines when the file contains no NUL. Empty entries are ignored.

**Path validation**, applied to every entry before anything is opened:

- valid UTF-8; no NUL or control characters (U+0000–U+001F, U+007F); at most 4096 bytes, each component at most 255 bytes;
- relative: not starting with `/`; no empty, `.` or `..` component; no backslash and no `:`;
- no component that a file system could map to `.git` (git's `is_hfs_dotgit` and `is_ntfs_dotgit` rules): compared case-folded (Unicode casefold) after removing Unicode ignorable code points and trailing dots and spaces, so `.GIT`, `.Git`, `.git.` and `.git` followed by a space are refused, as is the short name `git~<n>`; error `git_component`;
- no path appears twice, or in both lists, compared case-folded; no path is a prefix directory of another path in either list; error `duplicate`.

Other violations of these rules are `invalid_path`.

**Source.** The record must be an `active` throwaway whose directory exists ([Commands by record state](#commands-by-record-state)) and that is not [in use](#in-use-detection) (exit 20, `reason: in_use`).

**Reading** (files to copy), under the per-record lease: the throwaway root is opened with `O_DIRECTORY|O_NOFOLLOW` and must have the record's `root_id`, and the throwaway directory its `dir_id` (else `not_found`); each directory component is opened relative to its parent's fd with `O_RDONLY|O_DIRECTORY|O_NOFOLLOW`; the final component with `O_RDONLY|O_NOFOLLOW|O_NONBLOCK`. Every opened fd (directories and the file) must be on the throwaway root's device and, on Linux, mount; a path that crosses a [mount point](#mount-points) is `not_found`. The opened file must be a regular file (`fstat`), have link count 1 and fit `extract.max_file_bytes`; the total must fit `extract.max_total_bytes` and the count `extract.max_files`. Contents are read from the opened fd into memory.

**Destination.** `--dest` must be an existing directory (exit 2 otherwise) that is not inside wtctl's state dir, not inside the source throwaway, inside another throwaway only when that throwaway is an `active` record, whose per-record lease `extract` then also holds (the [clean checkout](#clean-checkout-for-confirm)), and without a `.git` component. It is opened with `O_DIRECTORY|O_NOFOLLOW` on its final component; when it lies inside a throwaway, the throwaway root and directory must have that record's `root_id` and `dir_id`, and every directory from the throwaway root down to it is opened no-follow and must be on the root's device and mount, else `dest_conflict` ([Mount points](#mount-points)). Each directory component below it is opened the same no-follow way; a missing directory is created with mode 0755 (`mkdirat`) and then opened no-follow. A component that is a [mount point](#mount-points) (relative to the `--dest` directory) is `dest_conflict`. An existing target must be a regular file (checked with `fstatat` and `AT_SYMLINK_NOFOLLOW`; a directory, symlink or other type is `dest_conflict`); it keeps its mode. A new file gets mode 0644. Content is written to a temporary file `.wtctl-extract-<random>` in the same directory (via the directory fd, `O_CREAT|O_EXCL|O_NOFOLLOW`), `fsync`ed, and renamed over the target relative to the directory fd. Deletions remove only regular files (`unlinkat` after a no-follow `fstatat`); a missing target is reported `absent`, not an error; a directory, symlink or other type at a deletion target is `dest_conflict`.

**All or nothing.** Every path is validated, every source opened and read, and every destination component checked before anything is written. Any problem exits 12, `error.code: extract_invalid`, with a per-path `error` (`invalid_path`, `git_component`, `duplicate`, `not_found`, `not_regular`, `symlink`, `hard_link`, `too_large`, `limit_exceeded`, `dest_conflict`) and writes nothing; `symlink` and `not_regular` describe the source, `dest_conflict` the destination. An I/O error while writing or deleting exits 1, `error.code: io_error`, with `details: {path, written, deleted}`: the path that failed and the paths already written and deleted (the destination is then partly changed). `--dry-run` performs every check and writes nothing.

### Clean checkout for confirm

A consumer recipe (review-respond's confirm, architecture §5.3 and §10.3) for committing agent-written changes without running anything in the agent's throwaway:

1. `wtctl create --throwaway --repo <id> --ref <PR head sha> --source remote` (default `--depth`): a second, fresh throwaway that is never handed to an agent or any untrusted process. `--source remote` keeps its objects out of the local clone, whose object store a trusted agent of that clone could have altered; it still fetches from the clone's [clone fetch URL](#clone-resolution) (the transport and credentials of the push) unless `repos.<id>.clone_url` is set. When `repos.<id>.clone_url` is a mirror, the clean checkout fetches from the mirror and may lag behind (`ref_not_found` for a fresh head); the push target in step 3 is always the clone fetch URL.
2. `wtctl extract <agent throwaway> --files-from … --delete-from … --dest <clean throwaway path>`.
3. In the clean throwaway, the consumer commits and pushes with the hardened invocation (architecture §13.2 rule 10) to an explicit URL: the `fetch_url` of `wtctl locate <repo> --json` (the [clone fetch URL](#clone-resolution); not the throwaway's `fetch_url`). Credentials for the push are the consumer's own, from its own config; wtctl's token settings are internal. A pull request whose head lives in a fork is pushed to the fork, which is outside wtctl. Filters are off there, which matches what the agent saw. A fast-forward push from a shallow throwaway works ([live verification](design.md#live-verification)). The consumer pushes with `--porcelain` and treats a rejected ref (a line starting with `!`, e.g. `[rejected] (fetch first)` or `(non-fast-forward)`) as the remote having moved; `[remote rejected] (shallow update not allowed)` means the remote lacks the base history. It never enables `receive.shallowUpdate` on a remote.
4. `wtctl remove` both throwaways, also after a refused push.

wtctl itself runs no git in either throwaway after creating it. `extract` writes only listed regular files into the clean throwaway, and no untrusted process ever runs in it.

## Reconcile

[`reconcile`](#reconcile-1) repairs wtctl's records and the clones' worktree metadata against reality. It never deletes a file in a worktree, never deletes a branch and never runs `git worktree prune` or `git worktree repair` (repair rewrites the pointers of every admin entry, including ones an agent planted, and so could write a `.git` file into any directory). Before changing a record it takes that record's per-record lease without waiting; a record whose lease a live process holds (a running create, remove or bootstrap) is skipped and not reported. Every state transition is a compare-and-set ([Locking](#audit-and-log)).

- **Unlinked** records (directory present, pointers mismatched; reconcile sets the state): wtctl **rewrites the two pointers itself**, only when the recorded `admin_dir` exists, the worktree directory at the recorded path has the recorded `dir_id` (opened as in [Remove order](#remove-order) step 9), and `<path>/.git` is missing or a regular file naming the recorded `admin_dir`; never when it names another existing admin entry (reported `unlinked`). It writes `<path>/.git` (`gitdir: <admin_dir>`) and `<admin_dir>/gitdir` (`<path>/.git`). The admin entry's directory fd is obtained one component at a time with `O_NOFOLLOW|O_DIRECTORY` from a file descriptor of the recorded common dir (as [Integrity](#integrity) reads it, with the recorded `common_id`), never by path, and must `fstat` as a directory owned by the invoking user on the common dir's device and mount ([Mount points](#mount-points)); otherwise nothing is written and the record stays `unlinked`. Each pointer is written to a temporary file created with `O_CREAT|O_EXCL|O_NOFOLLOW` in the same directory and renamed over the target relative to the directory fd, and it never writes a `.git` file anywhere else. Success is verified by re-running the [integrity](#integrity) checks. Still mismatched → stays `unlinked`, reported.
- **Missing** directories: the record becomes `missing` and `missing_since` is set at the first observation; a directory that reappears returns it to `active`. For an **owned** record, wtctl deletes its own admin entry `<common>/worktrees/<n>/` (the name validated against `admin_dir`, opened through the no-follow fd chain from the recorded common dir, which must have the recorded `common_id`, the entry and every directory on the chain on the common dir's device and mount, else the entry is kept and the record reported `unlinked`; deletion fd-based and no-follow, never crossing a [mount point](#mount-points)) and marks the record `gone` only when all hold: it has been `missing` for at least `reconcile.missing_grace` and seen missing by at least two runs; the entry has no `locked` file; the entry's `gitdir` file still names the recorded path; the entry's HEAD commit is reachable from a local branch (hardened `rev-list` in the clone with protocols `none`, content-verified as in [Reachability](#reachability)) or [pushed](#reachability); the entry has no `modules/` directory (a linked worktree's submodule git dirs) and no file below its `refs/` directory (per-worktree refs such as `refs/worktree/*` and `refs/bisect/*`); and every commit named by an entry of `<admin_dir>/logs/HEAD` since the recorded reflog start (attributed as in the `unpushed_branches` [content check](#content-checks)) is [pushed](#reachability) (a missing or unreadable reflog, or no usable anchor, fails this). An entry that fails any of the last three is kept and reported (`kept_unpushed`, with `tip` the entry's HEAD or the first unpushed reflog commit and a `message` naming the condition). If the branch tip is not [pushed](#reachability) (the [mirror](#mirror) is refreshed first; on refresh failure `fetch_failed` is reported, nothing counts as pushed, and an entry that needs a pushed commit is kept), it reports `gone_with_unpushed` with the branch and tip; the branch is kept. An owned record whose admin entry is already gone (no entry under the common dir has a `gitdir` file naming the recorded path, e.g. after a manual `git worktree remove` or `git worktree prune`) becomes `gone` after the same grace period and two observations, with nothing to delete, reported `gone` with `admin_entry: absent` (and the branch, if `created_branch` and it exists; it is kept). An **adopted** record's clone is never touched: after the grace period the record becomes `gone`, reported (`adopted_gone`).
- **Moved clones:** a record whose clone path is gone is re-resolved through [Clone resolution](#clone-resolution) (no auto-clone), but reconcile never re-attaches it and never changes a recorded identity: the record becomes `clone_missing`. When the re-resolved clone's `worktrees/<admin name>/gitdir` names the record's path (for a main-worktree record: the clone path equals the recorded path), reconcile reports `moved_clone` with the candidate's `clone_path`; a human verifies the candidate and runs [`baseline accept`](#baseline-accept) on the record, which re-attaches it. Otherwise it reports `clone_missing`.
- **Creating** records whose per-record lease is free (the creator died; age alone never matters). Bootstrap steps and network git calls run in their own process groups and can outlive a killed creator, so reconcile first runs the [in-use](#in-use-detection) check on the planned path: while a process is in it, the record is skipped and reported (`abandoned`). Otherwise:
  - A worktree whose planned path holds a `.git` file naming an admin entry under the recorded common dir, whose `gitdir` file names the planned path, is adopted after the crash: wtctl records `admin_dir` from it, `dir_id` (the planned path opened no-follow from `base_dir`), and records the baseline, the reflog start and the stash entry ids now; the record keeps its holders, gets `bootstrap.state: "interrupted"` with an empty bootstrap-created set (bootstrap may have run partly; nothing it made is exempt, so an automated removal will likely refuse `dirty` and need a human), and becomes `active`, reported (`adopted_after_crash`). A retried `create --holder` with one of its holders then returns it ([Retry after a crash](#create-order)).
  - A worktree whose planned path does not exist becomes `gone`, reported (`abandoned`, with the branch if `created_branch` and the branch exists; it is kept).
  - A worktree whose planned path exists but is not that worktree stays `creating` for a human ([`forget`](#forget)), reported (`abandoned`).
  - A throwaway's directory is deleted fd-based ([Throwaway removal](#throwaway-removal)) only when the record has its `dir_id` and the root and the directory have their recorded identities; otherwise (the creator died before recording `dir_id`, or an identity differs) the directory is left. Either way the record becomes `gone`; a directory left behind is then reported `stray`. No `pre-remove` or `post-remove` hooks fire (reconcile has no actor context for them).
- **Throwaways and strays:** a throwaway record whose directory vanished becomes `gone`; a directory under the throwaway root with no live record, and a leftover `*.wtctl-tmp-*` directory from an interrupted [clone](#clone-resolution) (under `clone_root` or next to a configured `repos.<id>.clone`), is reported as `stray` (never deleted). So is an entry of `${XDG_STATE_HOME:-~/.local/state}/wtctl/mirrors/` that no clone in `state.db` names as its `mirror_path` (an orphaned [mirror](#mirror), for example after a clone moved or was forgotten). A `stray` report's `kind_of` is `throwaway`, `clone_tmp` or `mirror`.
- **Foreign** worktrees (git lists them, wtctl has no record) are reported only by `list --all`.
- **Tombstones** older than `tombstone_days` are deleted.

`--dry-run` reports what would change. `post-reconcile` fires when something changed.

## Commands

### Check order

Every command runs these stages in order; a failing stage ends the command:

1. Usage and config (exit 2; `config_invalid`).
2. git version where git is needed (exit 12, `git_too_old`).
3. Record resolution (exit 2, 10 or 21) and clone resolution (exit 10, 12 or 21).
4. The command's own steps ([Create order](#create-order), [Remove order](#remove-order), …).

**Common exit codes.** Every command may also exit 1 (`internal`); every git-using command may exit 12 `git_too_old`; every command that takes a lease may exit 12 `busy` (after waiting up to `lease_wait`), except `status` and `remove --dry-run`, which never do ([`status`](#status)). The per-command lists below omit these. `busy` is a transient lease conflict (retry later, as termctl's `locked`); a target that is in use is the refusal `in_use` (exit 20).

**Record object.** Commands that print records use `schemas/cli/record.json`: `id`, `object_type`, `owned`, `state`, `repo`, `clone_path`, `common_dir`, `common_id`, `admin_dir`, `dir_id`, `base_dir`, `root_id`, `path`, `name`, `branch`, `created_branch`, `base`, `base_sha`, `head_at_create`, `ref`, `source`, `depth`, `fetch_url`, `remote`, `labels`, `holders`, `baseline_digest`, `bootstrap` (`state`: `none`, `ok`, `failed`, `interrupted` (a create reclaimed by [Reconcile](#reconcile) after a crash); `steps`; `created_paths_count`), `created`, `updated`, `missing_since`, `removed_at`, `last_error`. Fields that do not apply are `null` (`owned` is null for throwaways; `admin_dir` is null for main worktrees and throwaways). `common_id`, `dir_id` and `root_id` are recorded anchor identities ([Mount points](#mount-points)), each a `(st_dev, st_ino)` as `"<dev>:<ino>"`: `common_id` is the clone's common dir ([Anchor identity](#clone-resolution); worktrees only, null for throwaways); `dir_id` is the worktree or throwaway directory, recorded at create (a throwaway's at [step 7](#throwaway-create-order)), adopt or a reclaim after a crash and checked before wtctl deletes or rewrites anything by path ([Integrity](#integrity)); `root_id` is the throwaway root (throwaways only, null for worktrees). `dir_id` is null only while `creating`, and in a `gone` or `forgotten` tombstone of a record that never left `creating`. `baseline accept` (a human) is the only way a record's recorded identity changes; wtctl never re-records one by itself ([Anchor identity](#clone-resolution)). `base_dir` is the resolved realpath root the record's path lives under: the worktree root for an owned worktree, the throwaway root for a throwaway; null for adopted records. It is not the `root` config key. `holders` is a sorted array (empty for throwaways). A `creating` throwaway has `source` as requested (possibly `auto`) and a null `fetch_url`. `branch` is the branch at create, not the current one ([`status`](#status) reports that). `bootstrap.steps[].output_tail` and `last_error` are untrusted. Shapes not spelled out here are defined in `schemas/defs.json` (check object, baseline item, reconcile change and report).

**Dry runs.** `--dry-run` is accepted by `create`, `bootstrap`, `extract`, `baseline accept`, `adopt`, `forget`, `label add`, `label remove`, `clone`, `reconcile`, `prune`, `cron install`, `cron uninstall` and `remove`. It performs every check, prints what the command would do with `"dry_run": true`, and changes nothing (no hooks run, no prompt). `create --dry-run` runs the [Create order](#create-order) step 8 [mirror](#mirror) refresh (its only change, as for `status`) but never copies a base commit into the clone, so `branch_action` and `base_sha` are current; `create --throwaway --dry-run` fetches nothing, so it cannot detect a `ref_not_found` from a remote. `remove --dry-run` is identical to [`status`](#status) with the same arguments (it accepts `--merged-head` and `--holder`): it prints the status object with `"dry_run": true` and exits 0 whatever it found; it changes nothing except the mirror refresh and runs no hooks or confirmation. Human-only flags (`--force`, `--override-escalation`) still exit 2 without a human actor under `--dry-run`; otherwise `remove --dry-run` ignores `--force` (`force_overrides` shows its effect) and also ignores `--keep-branch`, `--yes` and `--hook`.

**Human output** escapes control characters in names, paths and output tails as `\xNN`.

### Commands by record state

What each single-target command does with a record in each state (exit code and outcome). A state-dependent condition exits 20 (or 10 for a tombstone), never 2; exit 2 is reserved for usage, including a command applied to the wrong object type: `bootstrap`, `baseline check|accept`, `forget` and `adopt` (a path in the throwaway root) refuse throwaways, and `extract` refuses worktrees, with exit 2 in every live state (a full id naming a tombstone exits 10 first, since record resolution comes before the command's own checks).

| State | `show` | `status` | `remove` | `bootstrap` | `extract` | `baseline check` / `accept` | `adopt` (its path) | `forget` | `label` |
|---|---|---|---|---|---|---|---|---|---|
| `creating` | 0 | 0, `reason: unlinked` | 20 `unlinked` | 20 `unlinked` | 20 `unlinked` | 20 `unlinked` | 20 `path_exists` with `holder_id` | 0 | 0 |
| `active` | 0 | 0 | [Remove order](#remove-order), [Throwaway removal](#throwaway-removal) | [Re-run](#bootstrap) (owned only; adopted: 20 `not_owned`) | [Extraction rules](#extraction-rules) | [`baseline check`](#baseline-check), [`baseline accept`](#baseline-accept) | 0, `existing: true` | [`forget`](#forget) | 0 |
| `unlinked`, `missing`, `clone_missing` | 0 | 0, `reason: unlinked` (checks that run git `skipped`) | 20 `unlinked` | 20 `unlinked` | (never a throwaway state) | 20 `unlinked` (`clone_missing`: `baseline accept` re-attaches a [moved clone](#baseline-accept)) | 20 `unlinked` (`missing`: 10, the path is not a git worktree) | 0 | 0 |
| `partial` | 0 | 0 (worktree: as [Partial records](#remove-order), `human_required: true`) | [Partial records](#remove-order) (worktree, human-only); [Throwaway removal](#throwaway-removal) (throwaway) | 20 `unlinked` | 20 `unlinked` | 20 `unlinked` | 20 `unlinked` | 0 | 0 |
| `gone`, `removed`, `forgotten` | 0 (full id) | 10 | 10 | 10 | 10 | 10 | 0, a new record | 10 | 10 |

- **Tombstones:** only a full id finds one ([Identifiers](#identifiers)); the 10 carries `error.details: {state, removed_at}`. A path never matches a tombstone, so `adopt` of a tombstone's path records it anew.
- **`forget`** follows its own rules in every live state (plain `forget` is human-only; `--holder` removes a holder).
- **A throwaway whose directory vanished** while its record is still `active` (before [Reconcile](#reconcile) saw it): `remove` marks it `gone` and exits 0 with a warning; `extract` exits 20, `unlinked`.
- **A live creator.** Commands that take the per-record lease (`remove`, `bootstrap`, `extract`, `baseline accept`, `adopt` of its path, `forget`, `label`) wait for a `creating` record's lease while its creator is alive and then exit 12, `busy`; the `creating` row shows the outcome once the creator has died.
- **A crashed create** leaves a `creating` record; a retried `create` reports `branch_in_use` or `path_exists` with its `holder_id` until [Reconcile](#reconcile) settles it. Then a retry succeeds normally if the record became `gone`; if it was reclaimed (`adopted_after_crash`), a retry with one of its holders gets it back with `"reused": true` ([Retry after a crash](#create-order)), and any other retry is still refused.

### `create`

```text
wtctl create --repo <repo-id> [--branch B | --detach] [--base BRANCH] [--ref SHA] [--name N] [--holder H]
             [--label k=v]... [--no-bootstrap] [--copy-env] [--hook NAME=CMD]...
             [--override-escalation] [--actor A] [--decision-id ID]...
wtctl create --throwaway --repo <repo-id> --ref SHA [--source auto|local|remote] [--depth N]
             [--label k=v]... [--hook NAME=CMD]... [--override-escalation] [--actor A] [--decision-id ID]...
```

Creates a worktree ([Create order](#create-order)) or a throwaway ([Throwaway create order](#throwaway-create-order)). A caller that creates a worktree at a commit it did not author (a third party's branch or sha) should pass `--no-bootstrap`, since bootstrap runs the project's own commands from that commit. `--holder` records a [holder](#records). Human output: the path only on stdout (a summary on stderr), like `locate`; also after `bootstrap_failed`, since the worktree exists. `--json`: `{"record", "branch_action", "bootstrap", "reused", "warnings", "dry_run"}` (`schemas/cli/create.json`; `branch_action` is null for throwaways; `reused` is true only for a [retry after a crash](#create-order), with `branch_action` and `bootstrap` null). Exit 0, 2, 10, 11, 12 (`remote_mismatch`, `clone_failed`, `auth_required`, `fetch_failed`, `ref_not_found`, `create_failed`, `unsafe_repo_config`, `bootstrap_failed`), 13, 20 (`branch_in_use`, `branch_exists`, `path_exists`), 21.

### `list`

`wtctl list [--repo <id>] [--label k=v]... [--throwaways | --worktrees] [--older-than DURATION] [--state S]... [--all]` lists records, newest first. Filters AND together; `--older-than` compares `created`. `--all` adds **foreign** entries: worktrees git lists for clones wtctl has records or config for, without a record (`{"foreign": true, "path", "branch", "head", "clone_path"}`). Human output: a table of id, type, state, repo, name or ref, branch, age. `--json`: `{"records": [...], "foreign": [...]}` (`schemas/cli/list.json`). Exit 0, 2.

### `show`

`wtctl show <id|path>` prints one record from `state.db`, running no git; a full id also finds a tombstone. `--json`: the record (`schemas/cli/show.json`). Exit 0, 2, 10, 21.

### `status`

`wtctl status <id|path> [--merged-head SHA] [--holder H]` runs [Remove order](#remove-order) steps 1 to 6 for a worktree (or the in-use check for a throwaway) and reports what `remove` with the same flags, run by a human, would do; `remove --dry-run` prints the same object with `"dry_run": true` ([Dry runs](#check-order)). It takes no per-record lease, no confirmation and fires no hooks. Its mirror refresh takes the per-clone lease but waits for it at most 5 seconds, not `lease_wait` (a create may hold it through long `pre-create` hooks): when the wait expires, `checks.fetch` is `skipped` with a warning, the checks that need tips are `skipped` and `would_remove` is null; `status` never exits `busy`. `remove` keeps `lease_wait`. Unlike `remove` it does not stop at the first refusal: `main_worktree` and `locked` are reported as `reason` (precedence as in [Remove order](#remove-order)) and every check still runs; an integrity failure (also for a `missing` or `clone_missing` record) skips only the checks that run git (`fetch` and the content checks, reported `skipped`); a failed refresh (also with no network) is `checks.fetch.status: "fail"` with the checks that need its tips (`unpushed_head`, `unpushed_branches`, `stash`) reported `skipped`, never `fail`. `--json`: `{"id", "object_type", "would_remove", "reason", "human_required", "checks", "force_overrides", "head", "current_branch", "warnings"}` (`schemas/cli/status.json`): `would_remove` is `true`, `false` (with `reason`, the refusal remove would give) or `null` (no refusal found, but it could not be determined because the mirror refresh failed or was skipped; `reason` null); `human_required` is true when `remove` is a [human-only command](#audit-and-log) for this record (adopted, or a `partial` worktree); then every check result, the failed checks a human `--force` would override, the worktree's current `HEAD` and branch (null when detached, and for throwaways). Exit 0 (whatever the checks found), 2, 10, 21.

### `remove`

```text
wtctl remove <id|path> [--merged-head SHA] [--keep-branch] [--holder H] [--force] [--yes]
             [--hook NAME=CMD]... [--override-escalation] [--actor A] [--decision-id ID]...
```

Removes a worktree ([Remove order](#remove-order)) or a throwaway ([Throwaway removal](#throwaway-removal)). `--merged-head` is a full 40-hex sha. `--holder` names the caller's own [holder](#records), which does not block the removal. `--json`: `{"record", "checks", "overridden", "branch_deleted", "branch_kept_reason", "warnings"}` (`schemas/cli/remove.json`); `overridden` names the checks a human `--force` overrode (empty when nothing was forced); on a refusal the error object carries `reason` and `checks` (`schemas/cli/error.json`). With `--dry-run` it prints the [`status`](#status) object plus `"dry_run": true` (the second branch of `schemas/cli/remove.json`) and exits 0, 2, 10 or 21, as `status` does. Exit 0, 1 (`partial`), 2, 10, 11, 12 (`fetch_failed`, `auth_required`), 13, 20 (`main_worktree`, `unlinked`, `locked`, `repo_config_changed`, `in_use`, `held`, `dirty`, `unpushed`), 21.

### `bootstrap`

`wtctl bootstrap <id|path> [--copy-env]` re-runs [Bootstrap](#bootstrap) on an owned, `active` worktree under the per-record lease; a human-only command. `--json`: `{"record", "bootstrap", "warnings", "dry_run"}` (`schemas/cli/bootstrap.json`). Exit 0, 2 (throwaway), 10, 12 (`bootstrap_failed`), 13, 20 (`not_owned`, `unlinked`, `repo_config_changed`, `in_use`), 21.

### `extract`

`wtctl extract <id|path> [--files-from FILE|-] [--delete-from FILE|-] --dest DIR [--max-size BYTES]` applies the [Extraction rules](#extraction-rules); at least one list is required. `--max-size` lowers `extract.max_file_bytes` for this call (it cannot raise it). The record must be a throwaway (else exit 2) in state `active` ([Commands by record state](#commands-by-record-state)). `--json`: `{"record_id", "dest", "written", "deleted", "dry_run"}` (`schemas/cli/extract.json`): `written` holds `{"path", "bytes", "mode", "created"}` with `mode` an octal string such as `"0644"`; `deleted` holds `{"path", "result"}` with `result` either `deleted` or `absent`. On `extract_invalid`, `error.details.paths` lists `{"path", "error"}`. Paths in the output are untrusted (agent-chosen). Exit 0, 1 (`io_error`), 2, 10, 12 (`extract_invalid`), 20 (`in_use`, `unlinked`), 21.

### `baseline check`

`wtctl baseline check <id|path>` runs [integrity](#integrity) first (`unlinked`, also for `creating`, `missing`, `clone_missing` and `partial` records), then recomputes the [baseline](#baseline) of a worktree record and compares it. It takes no lease. Unchanged: exit 0, `--json`: `{"id", "changed", "digest", "recorded_digest"}` (`schemas/cli/baseline-check.json`, `changed` always false). Changed in either class: exit 20, `reason: repo_config_changed`, and the error object (`schemas/cli/error.json`) carries `items` (each with its `class`) and `details: {digest, recorded_digest, changed_classes}`. Exit 0, 2 (throwaway), 10, 20 (`repo_config_changed`, `unlinked`), 21.

### `baseline accept`

`wtctl baseline accept <id|path> [--expect-digest D]` re-records the baseline after a human inspected the change; a human-only command, under the per-record lease. It runs integrity first like `baseline check`, except that a recorded anchor identity (`common_id`, `dir_id`, the worktree root's or a `core.hooksPath` item's) that differs from the location's current one, where the location otherwise passes integrity, does not refuse: it is shown with the changed items and re-recorded with them (`common_id` also in the clone's row, the worktree root's in the `anchors` table), for the case of a file system that presents a new `st_dev` after a reboot ([Mount points](#mount-points)). For every anchor of the record (`anchors`: `anchor`, `path`, `recorded`, `current`, `changed`, and the current `fs_type`, `mount_source` and `mount_point`, read on Linux from the `/proc/self/mountinfo` line of the opened fd's mount id and on macOS from `statfs`'s `f_fstypename`, `f_mntfromname` and `f_mntonname`) it shows where the location is mounted, so the human can tell a reboot from a mount an agent made. An anchor on a FUSE file system (Linux type `fuse` or `fuse.*`; macOS a `f_fstypename` containing `fuse`) is refused outright, with no override: exit 20, `reason: unlinked`, `details: {cause: "fuse_anchor", anchors}`. **A moved clone:** on a `clone_missing` record, `baseline accept` re-resolves the clone as [Reconcile](#reconcile) does and applies the same test (the candidate's `worktrees/<admin name>/gitdir` names the record's path; a main-worktree record: the clone path equals the recorded path), else exit 20, `reason: unlinked`; it shows the old and new clone path and common dir with the anchors, and on acceptance updates `clone_path`, `common_dir`, `common_id` and `admin_dir` (`<new common>/worktrees/<admin name>`) in the record and the clone's row (the clone's [mirror](#mirror) path is derived anew; the old mirror becomes an orphan), rewrites the two pointers under the per-clone lease as Reconcile's **Unlinked** repair does (the admin entry opened through the no-follow fd chain from the new common dir; never `git worktree repair`), re-runs the [integrity](#integrity) checks (a mismatch exits 20, `reason: unlinked`, and the record stays `clone_missing`) and makes the record `active` (a compare-and-set) with the re-recorded baseline. It computes and shows the changed items and asks unless `--yes`, then recomputes before writing and refuses (exit 20, `repo_config_changed`) if the digest changed since it was shown. `--expect-digest` (the `digest` a caller displayed, e.g. from `baseline check`'s error object) accepts only that state: a different current digest exits 20, `repo_config_changed`. With nothing changed it exits 0 with `items: []`. Audited (`baseline_accept`, with the changed items and anchors). `--json`: `{"record", "old_digest", "new_digest", "items", "anchors", "dry_run"}` (`schemas/cli/baseline-accept.json`). Exit 0, 2, 10, 13, 20 (`unlinked`, `repo_config_changed`), 21.

### `adopt`

`wtctl adopt <path> [--repo <id>] [--name N] [--holder H] [--label k=v]...` records an existing worktree or main worktree that wtctl did not create (`owned: false`): the `realpath` of `<path>` (so a symlinked ancestor never breaks later no-follow walks), the recorded URL ([clone fetch URL](#clone-resolution)), `common_id` ([Anchor identity](#clone-resolution)), `admin_dir`, `dir_id`, the baseline, the HEAD reflog start and the stash entry ids; no bootstrap. It runs under the per-clone lease. A SHA-256 repository exits 12, `create_failed`, `details.cause: object_format`; a changed common-dir identity exits 12, `create_failed`, `details.cause: anchor_changed` ([Anchor identity](#clone-resolution)). `<path>` must be the top level of a worktree (a subdirectory exits 2 with a hint naming the top level), must not be a submodule checkout (its `.git` names a directory under `<super>/.git/modules/`; exit 2 with a hint), and must not lie in wtctl's state dir or throwaway root (exit 2). `--repo` defaults to the repo id that the URL of the clone's `origin` remote normalizes to; once the id is known, the clone fetch URL is read and verified from `repos.<id>.remote` as usual. A clone without that remote exits 12, `remote_mismatch`, `details.cause: no_remote`. The name is `--name`, else derived from the path's basename ([Names](#identifiers)). `--holder` adds a [holder](#records). **An already recorded path:** `adopt` takes that record's per-record lease and acts only on an `active` record: it adds the `--holder` if given, in the same `state.db` transaction as a compare-and-set on the state, and returns the record (exit 0, `existing: true`), changing nothing else (labels and name are ignored); the record's `owned` tells the caller whether wtctl created it. A record in any other state is handled as in [Commands by record state](#commands-by-record-state) (exit 20 with its `reason`, or 10 when it became a tombstone while `adopt` waited). Audited (`adopt`). `--json`: `{"record", "existing", "dry_run"}` (`schemas/cli/adopt.json`). Exit 0, 2, 10 (not a git worktree), 12 (`remote_mismatch`, `create_failed`), 20 (`path_exists`, `unlinked`; [Commands by record state](#commands-by-record-state)).

### `forget`

`wtctl forget <id|path> [--holder H]` drops a worktree record without touching anything on disk (the worktree, its branch and the clone's metadata stay), under the per-record lease. With `--holder H`: if `H` is a holder it is removed, and the record becomes `forgotten` only when this call removed the last holder and the record is adopted (an owned record is never forgotten through `--holder`); if `H` is not a holder, nothing changes and the command exits 0 with the warning `not_a_holder` (so a retried teardown is harmless; a retry after the first call made the record `forgotten` exits 10 with `details.state: forgotten`, which an idempotent caller treats as done, [Identifiers](#identifiers)). Plain `forget` (no `--holder`) marks any live worktree record `forgotten`, whatever its holders; it is a human-only command. Throwaways are refused (exit 2; use `remove`). `--json`: `{"record", "warnings", "dry_run"}` (`schemas/cli/forget.json`). Exit 0, 2, 10, 13, 21.

### `locate`

`wtctl locate <repo-id>` resolves the clone ([Clone resolution](#clone-resolution)), which may auto-clone; read-only otherwise (apart from storing the verified clone fetch URL). `fetch_url` is the [clone fetch URL](#clone-resolution). `default_branch` is read from the clone's [mirror](#mirror) `HEAD`, as set by its last refresh (null when the mirror was never refreshed); `locate` never reads it from the clone and runs no network git for it. A SHA-256 clone is located with a warning on stderr ([Object format](#clone-resolution)). `--json`: `{"repo", "clone_path", "common_dir", "source": "config"|"discovered"|"cloned", "fetch_url", "default_branch"}` (`schemas/cli/locate.json`). Human output: the clone path only, so `cd "$(wtctl locate ...)"` works. Exit 0, 2, 10, 12 (`remote_mismatch`, `clone_failed`, `auth_required`), 20 (`path_exists`), 21.

### `clone`

`wtctl clone <repo-id>` clones the repo regardless of `auto_clone`. If the repo already resolves, it returns that clone (exit 0, `cloned: false`). **Re-accepting a clone:** when the resolved clone's common dir identity differs from `clones.common_id` ([Anchor identity](#clone-resolution)), `clone` re-records the clone's row only with a [human actor](#audit-and-log), under the per-repo lease: it shows the recorded and current identity with the current file-system type, mount source and mount point (`anchors`, as in [`baseline accept`](#baseline-accept)), refuses a FUSE file system outright (exit 20, `reason: unlinked`, `details.cause: fuse_anchor`), asks unless `--yes`, and records the current identity (and the clone's path and common dir when they changed; the [mirror](#mirror) path is then derived anew and the old mirror becomes an orphan). Live records keep their own `common_id` until a human `baseline accept`. Without a human actor it exits 13, `confirmation_required`, changing nothing. Audited (`clone_accept`). Otherwise the destination is `repos.<id>.clone` when that is configured (and missing), else its [location](#locations), and cloning follows **Cloning** in [Clone resolution](#clone-resolution); a destination that already holds a clone of this repo is recorded and returned (`cloned: false`). `--json`: the `locate` object plus `cloned`, `anchors` (empty unless a changed identity was shown) and `dry_run` (`schemas/cli/clone.json`). Exit 0, 2, 12 (`clone_failed`, `auth_required`, `remote_mismatch`), 13, 20 (`path_exists`, `unlinked`), 21.

### `label add` / `label remove`

`wtctl label add <id|path> k=v...` and `wtctl label remove <id|path> k=v...` edit a live record's labels ([Labels](#labels)) under the per-record lease. `--json`: `{"id", "labels", "dry_run"}` (`schemas/cli/label-add.json`, `schemas/cli/label-remove.json`). Exit 0, 2, 10, 21.

### `reconcile`

`wtctl reconcile [--dry-run]` runs [Reconcile](#reconcile) under the global lease; if the lease is still held after `lease_wait` it exits 0 with `"already_running": true`. `--json`: `{"changes": [{"id", "from", "to", "action"}], "reports": [{"kind": "gone"|"gone_with_unpushed"|"kept_unpushed"|"adopted_gone"|"adopted_after_crash"|"abandoned"|"stray"|"unlinked"|"clone_missing"|"moved_clone"|"fetch_failed", ...}], "already_running", "dry_run"}` (`schemas/cli/reconcile.json`; the fields of each change and report kind are in `schemas/defs.json`). Exit 0, 2.

### `prune`

`wtctl prune --throwaways [--older-than DURATION] [--if-configured] [--label k=v]... [--dry-run]` removes live throwaways older than `--older-than` (default `throwaway.max_age`) through [Throwaway removal](#throwaway-removal). If neither is set it exits 2, or, with `--if-configured`, removes no throwaway by age and only retries `partial` ones (so the cron entry always does something useful). Every run also retries every `partial` throwaway, whatever its age. Live throwaways that crashed callers left behind are removed only by age; nothing else reports them. It skips records with a label matching `prune.protect_labels` (a key or a `key=value` pair) and throwaways that are in use (reported with their processes), vetoed or escalated by a hook, or busy; a removal that fails (including a partial deletion) is reported `failed`, with the entries it could not delete in `paths`, and `prune` still exits 0. Runs under the global lease (exit 0 `already_running` if it is still held after `lease_wait`). `--json`: `{"removed", "skipped", "already_running", "dry_run"}` (`schemas/cli/prune.json`): `removed` lists ids; `skipped` lists `{"id", "reason", "processes", "paths"}` with `reason` one of `protected`, `in_use`, `vetoed`, `escalated`, `busy`, `failed`. Exit 0, 2.

### `export`

`wtctl export [--since TIME] [--audit | --log]` prints the records of `audit.jsonl` (default) or, with `--log`, of `log.jsonl`, oldest first: all of them, or those since `--since` (an RFC 3339 time or a DURATION). Without `--json`, one JSON record per line (JSONL); with `--json`, a JSON array whose items follow `schemas/audit.json` or `schemas/log.json` (`schemas/cli/export.json`). Read-only. Exit 0, 2.

### `cron install` / `cron uninstall`

`wtctl cron install` writes the managed crontab block `# wtctl managed` (design guide section 4.3) with an explicit `PATH` including `~/.local/bin` (on macOS also `/opt/homebrew/bin` and `/usr/local/bin`, each if it exists): `17 * * * * wtctl reconcile --actor auto:cron` and `47 * * * * wtctl prune --throwaways --if-configured --actor auto:cron` (distinct minutes, so the two rarely meet at the global lease, which each waits for up to `lease_wait`). `cron uninstall` removes the block. `--env-file FILE` adds a user-owned env-file prefix. `--json`: `{"installed", "entries", "dry_run"}` (`schemas/cli/cron-install.json`, `schemas/cli/cron-uninstall.json`); `entries` holds the crontab lines written or removed. Exit 0, 2.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | success (also `status` whatever it found, `already_running`, and `prune` with failed removals) |
| 1 | internal or unexpected error (`internal`), a partial deletion (`partial`), or an I/O error after `extract` started writing (`io_error`) |
| 2 | usage error, invalid config, a human-only flag without a human actor |
| 10 | not found (record, path, clone, repo, or a full id that names a tombstone) |
| 11 | a pre-hook vetoed |
| 12 | expected failure; `error.code`: `git_too_old`, `remote_mismatch`, `clone_failed`, `auth_required`, `fetch_failed`, `ref_not_found`, `create_failed`, `unsafe_repo_config`, `bootstrap_failed`, `extract_invalid`, `busy` |
| 13 | needs a human: `confirmation_required` (no TTY and no `--yes`, or a human-only command without a human actor) or `escalated` (a pre-hook escalated) |
| 20 | refused, with `reason` (below) |
| 21 | ambiguous selector, with `candidates` |

Refusal reasons: `dirty`, `unpushed` and `repo_config_changed` (shared, design guide section 4.2), and wtctl's own `branch_in_use`, `branch_exists`, `path_exists`, `in_use`, `held`, `unlinked`, `not_owned`, `main_worktree`, `locked`. `in_use` is wtctl's own reason, distinct from the shared `live` (which means a live agent session): wtctl cannot know about sessions, only processes. wtctl defines no tool-specific exit codes (22+).

## Hooks

Hooks follow design guide section 8: configured under `hooks.<name>` as a list of `{cmd, timeout, async}` (timeout default 30 seconds; `async` only for post-hooks), run with `sh -c` in their own process group, the payload as JSON on stdin, the environment of wtctl minus every `hosts.*.token_env` variable. `--hook NAME=CMD` (repeatable, on `create` and `remove`) adds a hook for this invocation after the configured ones.

| Hook | Fires | Can veto/escalate | Payload |
|---|---|---|---|
| `pre-create` | [Create order](#create-order) step 11 / [Throwaway create order](#throwaway-create-order) step 5 | yes | `schemas/hooks/pre-create.json`: `object_type`, `repo`, `clone_path`, planned `path`, `branch`, `branch_action` (see Create order step 9), `base`, `ref`, `source`, `labels`, `actor`, `decision_ids` |
| `post-create` | after the record and bootstrap (also after `bootstrap_failed`) | no | `schemas/hooks/post-create.json`: the record, `bootstrap` |
| `pre-remove` | [Remove order](#remove-order) step 8 (also when finishing a `partial` worktree, [Partial records](#remove-order)) / [Throwaway removal](#throwaway-removal) | yes | `schemas/hooks/pre-remove.json`: the record, `checks`, `merged_head`, `overridden`, `actor`, `decision_ids` |
| `post-remove` | after deletion | no | `schemas/hooks/post-remove.json`: the record, `branch_deleted`, `branch_kept_reason`, `overridden` |
| `post-reconcile` | after `reconcile` changed something | no | `schemas/hooks/post-reconcile.json`: `changes`, `reports` |
| `post-baseline-accept` | after `baseline accept` | no | `schemas/hooks/post-baseline-accept.json`: the record, `items`, `actor` |

Every payload carries `tool: "wtctl"`, `hook`, `object_type` (`worktree` or `throwaway`; `reconcile` for `post-reconcile`), `object_id` (the record id, allocated before `pre-create`; null for `post-reconcile`), `repo` and `labels`. In `pre-create`, `source` is the requested mode (`auto` possible); the record's `source` is the one used. `overridden` names the checks a human `--force` overrode (empty when nothing was forced). Hook processes get `WTCTL_HOOK`, `WTCTL_ID` and `WTCTL_OBJECT_TYPE`.

**Outcomes.** Pre-hooks run in order: exit 0 continues; exit 13 escalates (the remaining hooks still run); any other non-zero exit, or a timeout, vetoes immediately (exit 11). If none vetoed and any escalated, the command exits 13 (`escalated`) having changed nothing. With `--override-escalation` (a [human-only flag](#audit-and-log)), a hook's exit 13 counts as allow; other outcomes are unchanged. Post-hook failures are logged and warned, never fatal.

**Decision ids.** A hook that prints a JSON object with `decision_id` (a string or a list) on stdout has it recorded in the log record of the step and, for audited actions, in the audit record ([Identifiers](#identifiers)).

## Config

`~/.config/wtctl/config.yaml` (`$XDG_CONFIG_HOME` respected; the same path on macOS), then `config.d/*.yaml` in lexical order (maps merge, lists replace except `hooks.<name>` lists, which append). Validated against `schemas/config.json` (every key, with its default, in `config.example.yaml`); invalid config exits 2 naming the key. Path keys accept an absolute path or a leading `~/` (expanded once); anything else exits 2. Precedence: flags > per-repo (`repos.<id>`) > environment > global config > built-in defaults.

| `throwaway_root` | null (`<root>/throwaway`) | [Locations](#locations) |

| `branch_template` | `wt/{name}` | [Create order](#create-order) step 7 |
| `branch_prefix` | `""` | prepended to template-built branch names only |
| `search_roots` | `[]` | [Clone resolution](#clone-resolution) discovery; empty = off |
| `search_depth` | 3 | discovery depth |
| `auto_clone` | false | auto-clone in `locate` and `--repo` resolution |
| `clone_root` | null (`<root>/clones`) | auto-clone location |
| `network_timeout` | `120s` | DURATION limit of mirror refreshes after the first, `ls-remote --symref` and shallow throwaway fetches ([Hardened git](#hardened-git)) |
| `clone_timeout` | `30m` | DURATION limit of clones, a mirror's first refresh, base-commit tree fetches and `--depth 0` throwaway fetches ([Hardened git](#hardened-git)) |

## Environment

- **Config from the environment:** `WTCTL_<KEY>` for top-level scalar keys only (`WTCTL_ROOT`, `WTCTL_WORKTREE_ROOT`, `WTCTL_THROWAWAY_ROOT`, `WTCTL_CLONE_ROOT`, `WTCTL_WORKTREE_PATH`, `WTCTL_AUTO_CLONE`, `WTCTL_SEARCH_DEPTH`, `WTCTL_NETWORK_TIMEOUT`, `WTCTL_CLONE_TIMEOUT`, `WTCTL_LEASE_WAIT`, `WTCTL_TOMBSTONE_DAYS`, `WTCTL_GIT_BIN`, `WTCTL_BRANCH_TEMPLATE`, `WTCTL_BRANCH_PREFIX`). Booleans are `true`, `false`, `1` or `0`; integers are decimal; anything else exits 2. Structured keys (`repos`, `hosts`, `hooks`, lists) cannot be set from the environment.
- **Hook variables:** `WTCTL_HOOK`, `WTCTL_ID`, `WTCTL_OBJECT_TYPE` ([Hooks](#hooks)); bootstrap variables `WTCTL_ID`, `WTCTL_PATH`, `WTCTL_REPO` ([Bootstrap](#bootstrap)). These names are reserved and never read as config.
- **Credentials:** the variables named by `hosts.<host>.token_env`, read only when a network git operation needs them; `SSH_AUTH_SOCK` for SSH ([Credentials](#credentials)).
- **git's environment:** built from scratch for every git call ([Hardened git](#hardened-git)); nothing else from the caller's environment reaches git.

## Audit and log

- **`log.jsonl`** (`schemas/log.json`): one record per state-changing command, per mirror refresh or base-commit transfer and per hook run: `ts`, `level`, `event` (`create`, `throwaway_create`, `bootstrap`, `remove`, `throwaway_remove`, `refused`, `extract`, `baseline_accept`, `prune`, `reconcile`, `clone`, `discovered`, `adopt`, `forget`, `label`, `cron`, `fetch`, `hook`), `id`, `repo`, `actor`, `decision_ids`, `details`.
- **Log levels:** `error` for exit 1 (internal, partial), `warn` for refusals, vetoes, escalations, expected failures (exit 12) and post-hook failures, `info` for everything else.
- **`audit.jsonl`** (`schemas/audit.json`, design guide section 6): `ts`, `actor`, `decision_id`, `target`, `action`, `inputs`, `result`. Actions: `remove` (worktrees; `inputs`: HEAD sha, null when unknown, e.g. finishing a `partial` record; `merged_head`, baseline digest, `overridden` checks), `branch_delete` (branch, sha), `baseline_accept` (old and new digest, changed items), `adopt` (path, digest, holder), `clone_accept` (repo, clone path, recorded and current identity, mount information), `admin_entry_delete` (from `reconcile`: admin entry, its HEAD, branch, tip). `target` is the record id and path; `result` is `ok`, or `error` when the action failed after starting (e.g. a partial deletion). Throwaway create/remove, `prune` removals, `create`, bootstrap, `clone` and discovery are logged, not audited.
- **Actor.** `--actor` matches `^(human|auto):[A-Za-z0-9._@-]{1,64}$`. An explicit `--actor` always wins; only when it is absent does the TTY matter: the default is `human:<me.name>` when stdin is a TTY, else `auto:unknown`. A **human actor** is `--actor human:<user>`, or no `--actor` with stdin a TTY. **Human-only commands** (`baseline accept`, a `bootstrap` re-run, plain `forget`, `clone` re-accepting a changed clone identity, `remove` of an adopted record or of a `partial` worktree) exit 13, `confirmation_required`, without a human actor. **Human-only flags** (`--force`, `--override-escalation`) exit 2 without one. The gate is advisory against a caller that lies about its actor ([Residual risks](#residual-risks)).
- **Locking.** Leases in `state.db` (holder PID, process start time, expiry; a lease whose holder is dead is taken over; a held lease is renewed, including while wtctl waits for a prompt or a hook):
  - a **per-repo** lease (keyed by repo id) for [cloning](#clone-resolution) (auto-clone and `clone`);
  - a **per-clone** lease for git writes to a clone: create steps 5 to 13, remove steps 5 and 9 to 10, `adopt`, reconcile repairs, a moved-clone `baseline accept`, and every refresh of the clone's [mirror](#mirror) and base-commit transfer (also `status`'s refresh, which waits for it at most 5 seconds, [`status`](#status));
  - a **per-record** lease for `remove`, `extract` (also on an `active` destination throwaway), `bootstrap`, `baseline accept`, `forget`, `label add`/`label remove`, `adopt` of an already recorded path, and create from the record write through step 16 (taken in the same transaction as the record insert); [Reconcile](#reconcile) and [`prune`](#prune) take it without waiting and skip records whose lease is held (`prune` reports them `busy`);
  - a **global** lease for `reconcile` and `prune`.

  Read-only commands (`show`, `list`, `status`, `baseline check`, `locate` without auto-clone, `export`) take no per-record lease. A command waits up to `lease_wait` (default `10m`) for a held lease; then it exits 12, `error.code: busy` (callers retry later), or, for the global lease, 0 with `already_running`. Every state transition is a compare-and-set on the record's state; a command that loses the race exits 12, `busy` (or 10 if the record became a tombstone), except where a step says otherwise ([Create order](#create-order) step 16).
- **Secrets.** Tokens, header values and env-file contents never appear in state, logs, audit records, hook payloads or output; URLs are recorded without userinfo.

## Residual risks

- **The human-only gate is advisory.** A caller that passes `--actor human:<user>` without a human gets human-only behavior; automation in awkit never does (design guide section 4.4).
- **Trusted agents and the clone.** An agent running in a worktree can write the clone's shared git dir. The [baseline](#baseline) detects, but does not prevent, config, hook and pointer changes by trusted agents; a trusted agent that lies about a human actor can also re-record it with `baseline accept`. The `unpushed_branches` reflog check is defense in depth against trusted agents, not a guarantee: an agent that rewrites the reflog file (plain text, with timestamps the writer chooses) can hide a side branch from it, and committer dates can be backdated (`GIT_COMMITTER_DATE` sets the reflog timestamp), which the positional anchor catches only while the start entry exists; emptying it fails safe (`reflog_unavailable`). [Reachability](#reachability) re-hashes the commits it relies on, so a forged object store fails safe (unpushed). Hardened git keeps wtctl's own commands from running planted code either way.
- **wtctl's own state is not tamper-proof.** `state.db`, the [mirrors](#mirror) and wtctl's roots (worktree, throwaway and clone roots) are writable by any unsandboxed process of the user, trusted agents included. wtctl's guarantees against trusted agents cover their tampering with the clone's git config and with worktree content, not direct edits of wtctl's own state or mirrors (pointing a record's path elsewhere, exempting files, forging a mirror's refs so unpushed work looks pushed), which would be deliberate sabotage by a trusted agent. Sandboxed runs are denied these paths.
- **Reflog-only commits.** Commits made on a detached `HEAD` and then left are referenced only by the worktree's `HEAD` reflog. `remove` checks the current `HEAD` and side-branch tips, not such commits, so they are lost with the admin entry; [Reconcile](#reconcile) keeps an admin entry while its reflog names an unpushed commit.
- **Sparse checkouts** set skip-worktree on paths outside their cone, so `tracked` fails with `hidden_changes` and removal needs a human `--force` in v1 ([Content checks](#content-checks)).
- **Planted promisor remotes.** An agent can plant a promisor remote in the clone whose `uploadpack` runs a command, and delete objects so that git tries to fetch them lazily. wtctl's own git never runs it: every command against the clone runs with `GIT_ALLOW_PROTOCOL=none`, which blocks the lazy fetch on every supported git, also on builds before 2.45.1 that ignore `GIT_NO_LAZY_FETCH` ([Hardened git](#hardened-git)). Such tampering, or planted refs, can only make a base-commit transfer or a `local` throwaway fail (`create_failed`, `fetch_failed`). The user's own git in the clone, run without wtctl's recipe, is not protected.
- **File-system sabotage by a trusted agent is out of scope.** wtctl's file-system defenses (no-follow walks, recorded anchors, mount checks, bounds and deadlines) target planted configuration and mount tricks that would make wtctl itself destroy or misread data. A trusted, unsandboxed agent can always delete or alter the user's files directly, so deliberate file-system-level sabotage by such an agent is out of scope beyond these checks.
- **First recording is trust on first use** where wtctl did not create the location itself (a root created by hand, a configured or discovered clone, an adopted worktree): a mount already in place is recorded with it ([Mount points](#mount-points)).
- **Deadlines and anchor mounts.** A walk that needs more than its deadline (60 seconds, 300 seconds for one `remove`) on a slow or very large tree fails safe and needs a human (a `partial` record is finished by a later `remove`). An anchor directory that is itself a mount point (a throwaway root placed exactly at a mount point, for example) is refused on Linux; place roots inside the mounted file system.
- **Mount points on macOS** are detected by `st_dev` only, with no mountinfo pre-check, so a bind-style mount of the same file system would not be seen ([Mount points](#mount-points)). On Linux an unprivileged same-file-system bind mount exists only in the agent's own mount namespace, and the mount id catches it where wtctl can see it.
- **Honored filter drivers** run with the clone's config and the checkout's `.lfsconfig` as input. wtctl refuses the keys that are known to run commands or redirect traffic ([Hardened git](#hardened-git)); a driver may read others.
- **Races.** A process that edits the repository between [Remove order](#remove-order) step 9's re-check and the deletion can still lose work; the in-use check and callers' liveness checks (agent-spawn never removes a worktree with a live agent) are the mitigation. Step 9 does not re-run `nested_repos` (a full walk) or `unpushed_branches`, so a nested repository or a side branch created between step 6 and step 9 is not refused (the side branch itself survives in the clone).
- **Submodules.** v1 does not check submodules recursively: every worktree with an initialized submodule fails `nested_repos` (detail `submodule`), so its automated teardown always needs a human `--force` ([Content checks](#content-checks)).
- **Filters at removal.** Removal runs `git status` with every filter blanked. In a worktree checked out with an honored driver (git-lfs), racily clean index entries may be re-hashed without the clean filter and reported modified, a false `dirty` that fails safe but can block automated teardown right after create (not yet verified with real git-lfs).
- **In-use detection is best effort:** it sees only the invoking user's processes, misses processes that hold no cwd or file inside the directory, matches open files by path only (and everything by path on macOS), so a process that holds only an open file under another mount path is missed, and is skipped when no scanner exists.
- **One remote.** A branch pushed only to a remote other than `repos.<id>.remote` looks unpushed ([Remove order](#remove-order)).
- **Token stripping is accident prevention, not a boundary.** Bootstrap steps and hooks run as the user, and a process of the same user can read any ancestor's `/proc/<pid>/environ` (so every `token_env` value of the caller's shell) and the user's own credential stores. wtctl's `prctl(PR_SET_DUMPABLE, 0)` on Linux protects only a `token_command` token held in its own memory ([Credentials](#credentials)).
- **Binaries come from the caller's `PATH`** ([Hardened git](#hardened-git)): a caller whose `PATH` contains an agent-writable directory can make wtctl run a planted `git`, `lsof` or filter driver; set `git_bin` in automation.
- **Bootstrap runs project code** with the user's environment, minus HTTPS tokens (see above). It runs from steps in the user's own config, on owned worktrees: at create, before any agent touches the worktree (callers pass `--no-bootstrap` for commits they did not author), and on a human-only re-run, which may run code an agent changed since create.

## Platform notes

- Linux and WSL (Ubuntu 22.04 or newer) and macOS (Apple git 2.39 or a newer git). git 2.34 or newer.
- SHA-1 repositories only: SHA-256 repositories (`extensions.objectFormat=sha256`) are unsupported in v1. `create`, `create --throwaway` and `adopt` exit 12, `create_failed` (`details.cause: object_format`); `locate` and `clone` warn ([Object format](#clone-resolution)).
- Linux and WSL: wtctl makes itself non-dumpable at startup (`prctl(PR_SET_DUMPABLE, 0)`, [Credentials](#credentials)). On macOS it makes no equivalent call.
- WSL: a `root`, `worktree_root`, `throwaway_root`, clone or `clone_root` under `/mnt/` (Windows drives) is allowed with a warning (slow, case-insensitive, unreliable symlinks and file watching). In-use detection reads `/proc` of the Linux side only.
- macOS: in-use detection uses `lsof` and matches paths only (not verified against sandboxed processes); extraction and removal use per-component `openat` with `O_NOFOLLOW` (portable; no `openat2`); `.git` comparisons are case-folded because the default file system is case-insensitive. [Mount points](#mount-points) are detected by `st_dev` only (Linux also compares the mount id from `/proc/self/fdinfo/<fd>` and checks `/proc/self/mountinfo` before opening an anchor); mount information for [`baseline accept`](#baseline-accept) and [`clone`](#clone) comes from `statfs` (`f_fstypename`, `f_mntfromname`, `f_mntonname`).
- Paths containing a newline are refused ([Hardened git](#hardened-git)).
