# wtctl: design

Status: designed (interface 0.1.0-design), 2026-10-30. The interface, including every normative rule, is in [interface.md](interface.md); this document records the decisions, the internal architecture and the live verification behind them, and links to the interface instead of restating its rules.

## Role and layer

Git worktrees, throwaway checkouts, and the mapping from repo ids to local clones. Layer 1 (primitive); works fully standalone (architecture §2, C2) and is shareable, so it runs on Linux, WSL and macOS (C4). Consumers: agent-spawn (`locate`, `create --holder`, `status`, `baseline check`, `remove --holder`, `adopt --holder`/`forget --holder`), review-run (throwaways for `run_pr_code`), review-respond (a throwaway per respond round; on confirm a second, fresh throwaway as the clean checkout and `extract` into it) and ticket-work (`locate`).

## Constraints (from architecture §20)

- "Dirty" means any tracked change or any untracked, non-ignored file; ignored files are listed in the refusal unless bootstrap created them: [Content checks](interface.md#content-checks) (refined by D14: disposable globs and nested repositories).
- `remove` fetches first: [Remove order](interface.md#remove-order) step 5 (a refresh of wtctl's own mirror, D50; the user's clone is never the target of a network fetch).
- The stash check covers only stash entries based on the worktree's branch: [Content checks](interface.md#content-checks) (`stash`).
- The pushed check exempts the worktree's branch when HEAD equals `--merged-head` or is reachable from a remote ref: [Content checks](interface.md#content-checks) (`unpushed_head`; the remote tips are the `refs/heads/*` of wtctl's own mirror after a successful refresh from the recorded URL, D50, and reachability from them is verified by content, D31).
- Refusals exit 20 with a `reason`: [Exit codes](interface.md#exit-codes).
- Throwaways: `git init` plus only the given commit (a fetch by sha from the remote, or a pack of that commit's objects built from the local clone, D11, D54), never a clone of all local refs and objects, no persisted credentials: [Throwaway create order](interface.md#throwaway-create-order).

## Decisions

| # | Decision | Rationale |
|---|---|---|
| D1 | Worktrees go to a configurable template, by default `{root}/{host}/{path}/{name}` with `{root}` the worktree root (default `~/wtctl/worktrees`, D30); the root is resolved with realpath once at create and recorded (record field `base_dir`), and the rendered path must start with it ([Locations](interface.md#locations), [Integrity](interface.md#integrity)). | Never touches a clone's tree; works for auto-clones; predictable for `list` and `reconcile`. Spike B10: a worktree inside the clone makes it dirty, is picked up by `add -A` and is deleted by `clean -ffd`. Recording the resolved root keeps integrity stable when config changes or an ancestor of the root is a symlink. |
| D2 | An explicit `--branch` is used verbatim; otherwise `branch_prefix` + `branch_template` with `{name}`, `{id}`, `{date}` only ([Create order](interface.md#create-order), the name and branch step). | Ticket-specific naming (the ticket key as a whole token) belongs to ticket-work, which passes `--branch` through agent-spawn; a primitive gets no ticket knowledge. |
| D3 | A branch checked out anywhere in the clone is refused (`branch_in_use`), with no override. | Two checkouts of one branch let one agent's commits silently change the other's state; no awkit flow needs it (resume reuses the worktree). |
| D4 | New branches are created with `--no-track`; remote-only branches get an explicitly set upstream. Classification only reads: the branch and its upstream config are created when the worktree is added, after `pre-create`, so a veto leaves no ref or config change in the clone (at most the mirror refresh and base objects transferred from the mirror, D50) ([Create order](interface.md#create-order)). | Spike B1/surprise 4: `-b X origin/main` sets upstream to `main`, and with `push.default=upstream` a bare `git push` pushes onto `main`. Spike D3: git's remote-branch guessing needs a real remote entry and ignores `checkout.defaultRemote`. |
| D5 | Clone resolution: config, then opt-in discovery over `search_roots`, then opt-in auto-clone; explicit `clone` command ([Clone resolution](interface.md#clone-resolution)). A configured clone directory that does not exist is "not found" (exit 10, hint `wtctl clone`, which clones there), not `remote_mismatch`. | Config is explicit and always wins; discovery fits existing layouts (`~/dev`); auto-clone is convenient but off by default (public default). |
| D6 | Bootstrap runs on `create` when the repo has steps (`bootstrap.auto`), as argv steps with timeouts; package stores are plain `bootstrap.env` ([Bootstrap](interface.md#bootstrap)). | agent-spawn needs no new flag; no package-manager knowledge in wtctl. A failing step keeps the worktree (`bootstrap_failed`) so the caller decides. |
| D7 | Env-file copying is opt-in per call and per repo (`copy_env`, empty default); copies, never symlinks; mode 0600; a symlinked source is skipped with a warning (how "refused" is applied), and destination writes never follow links; the source walk opens every component no-follow from the clone root fd, never follows directory symlinks, and requires regular files with link count 1 (else skip with a warning) ([Bootstrap](interface.md#bootstrap) step 2). | Copying secrets into an agent's workdir is a per-repo decision; a symlink would let the agent edit the main clone's file. Safety check SAFE-9: a glob walk through a tracked directory symlink, or a hard link to `~/.ssh/id_*` named `.env`, would copy secrets from outside the clone into a worktree a later third-party-reading run may read. |
| D8 | No port or container slot allocation in v1. | Projects handle this in different ways; wtctl does not impose a standard. The architecture's "per-worktree port/container prefixes" was dropped (v1.10). |
| D9 | The hardened git recipe is normative in architecture §13.2 rule 10 and applied by every git call wtctl makes ([Hardened git](interface.md#hardened-git)). Review pass 1 added the spike E findings to the recipe: `GIT_NO_REPLACE_OBJECTS=1`, `GIT_GRAFT_FILE=/dev/null/none`, `core.useReplaceRefs=false`, `core.commitGraph=false`, `core.sshCommand="ssh -o BatchMode=yes"` with `GIT_SSH_VARIANT=ssh`, `http.followRedirects=false`, exact-name blanking of repository `http.*extraheader` keys, network timeouts (D39), and the allowed filter drivers' directories on `PATH`. The safety check added: every git command that is not meant to contact the network runs with `GIT_ALLOW_PROTOCOL=none` and `GIT_NO_LAZY_FETCH=1`, and network commands allow exactly the scheme they need; local repositories are addressed by plain absolute path, never `file://`; network git runs only in wtctl's own mirror (D50) or a fresh throwaway; every git command against an agent-writable repository runs with protocols `none`, with no exception, and objects move into or out of one only as packs wtctl builds and indexes itself, never by `fetch`, `clone` or `push` run against it (safety re-check, D54); `--no-ext-diff` is passed on every diff-family command, because with `-c diff.external=` git's `diff` otherwise fails (spike H surprise 6); wtctl never runs `git worktree remove` (D51) or `git worktree repair` (D52). | Spike C: the earlier flag set left about a dozen execution and redirection vectors open. Spike E1a–c: replace refs, grafts and a forged commit-graph make unpushed work look pushed; E4: ssh ignores `GIT_TERMINAL_PROMPT=0`; E5: scoped headers follow redirects and repository headers survive a blanket blank. A cross-tool safety invariant belongs in the architecture. Spike G5: a promisor remote planted in the clone runs its `uploadpack` whenever git reads a missing object (`status`, `worktree add`, `cat-file`), and `-c remote.<r>.uploadpack=` cannot override it; `GIT_ALLOW_PROTOCOL=none` blocks it on 2.34 and `GIT_NO_LAZY_FETCH=1` where git has it; a planted `remote.<file-url>.uploadpack` applies to `file://` URLs but never to a plain path. Safety check SAFE-3: `core.alternateRefsCommand` runs through the shell during fetch negotiation (an empty value prints an `error:` line, so the override is `true`); SAFE-2/SAFE-4: a fetch by URL reads `remote.<URL>.*` and URL-scoped `http.<url>.*` repository config, which force-moved local branches, overwrote a file through `http.cookieFile`, and sent the token across a redirect, to a proxy or past disabled TLS verification. |
| D10 | wtctl owns the repo-config baseline: recorded at `create` (after bootstrap) and `adopt`, checked by `remove` and `baseline check`, re-recorded by a human with `baseline accept`. Config files are parsed and hashed per key, minus a fail-safe exclusion list of routine branch and remote tracking keys (plus the user's `baseline.ignore_config_keys`); only the record's own admin entry counts (including its `modules/**` config and hooks, where a linked worktree keeps its submodules' git dirs, spike V2, as well as the clone's `modules/**`); `info/exclude` and the effective `core.excludesFile` are included. Items are `git` class or `claude` class (Claude project config, at any depth, including inside disposable and bootstrap-created directories; only nested `.git` directories and the sandbox's `.claude/.cc-writes/` are skipped, D41): `remove` refuses only on `git`-class changes and warns on `claude`; `baseline check` refuses on either ([Baseline](interface.md#baseline)). | One owner for the hash set and the hardened reads; the check happens at the moment of removal; closes agent-spawn's open topic of how a human clears `repo_config_changed`. Whole-file hashes changed on routine work (`git push -u`, wtctl's own branch config writes, sibling worktrees, bootstrap hook installers), so automated teardown would always stall on a human. Claude project config cannot run during wtctl's hardened removal, but a later trusted resume would load it, so the resume check keeps it. Excludes can turn untracked work into ignored, deletable files. Recording after bootstrap makes the project's own setup part of the baseline. Claude Code loads `CLAUDE.md` from subdirectories it works in, and a sandboxed session can write inside ignored directories, so the `claude` class skips no build or dependency directory (review pass 2). Spike V2: a linked worktree's submodule git dirs live under its admin entry, not under the common dir's `modules/`, so covering only the latter missed them in the main case (review pass 3). Approved by the user (2026-10-30). |
| D11 | Throwaway source: the local clone when it has the commit, else the remote by sha, from the first of `repos.<id>.clone_url`, the clone fetch URL (D46), `hosts.<host>.clone_url`; the clone is resolved for every `--source` (never auto-cloning; a resolution failure matters only for `local`), and `--source remote` reads only its fetch URL, never its objects; HTTPS tokens from `hosts.<host>.token_env` or `token_command` (D33), chosen by the host of the URL actually used and passed as a URL-scoped header through `GIT_CONFIG_COUNT`; SSH through the agent; never credential helpers; the probe whether the local clone has the commit runs with protocols `none` and `GIT_NO_LAZY_FETCH=1`, and a `local` source is copied as a pack built in the clone with protocols `none` and indexed with `--strict` in the fresh throwaway, never fetched from the clone (D54, [Mirror implementation notes](#mirror-implementation-notes)) ([Throwaway create order](interface.md#throwaway-create-order), [Credentials](interface.md#credentials)). | Spike A1/A6: fetch-by-sha works from a local clone (protocol v2, any full sha) and from GitHub/GitLab (fork PR and MR heads without fetching refs). Spike A7: config passed through the environment is never persisted. The user's credential helper would otherwise answer a 401. The clone fetch URL is already verified against the repo id and is often the user's SSH URL; resolving it only for `auto` and `local` sent `--source remote` (review-respond's clean checkout) to the anonymous HTTPS host template, which fails for a private repo the user reaches over SSH (review pass 3). Spike E5: a scoped header is not sent to other hosts, and with redirects off (D9) never follows one. |
| D12 | Remote throwaway fetches default to depth 50 (`throwaway.depth`; `0` = full). A local-source throwaway carries the full history of the commit by default, or depth 1 with `--depth 1` (the shallow file is written before indexing); any other `--depth` applies to remote fetches only: with `--source local` it exits 2, and with `--source auto` it makes `auto` prefer `remote`. `throwaway.depth` governs remote fetches only. | Spike A3: depth 1 breaks `diff HEAD~1`; depth 50 keeps history usable at a fraction of a full fetch. Spike H2: a local throwaway is a pack built in the clone (D54), and `pack-objects` has no depth-N primitive (no `--shallow-file`/`--depth`, and a `--max-count` boundary is wrong for merges), so only depth 1 or the full history is clean; full local history costs no network and little disk (18.5 KB against 7.7 KB for depth 1 in the spike; spike A3 sizes). |
| D13 | Throwaways are built with `init --template=`, isolated config, `info/attributes` `* -filter`, no reflog and no `FETCH_HEAD`. wtctl itself never runs git in a throwaway after creating it. A caller may run git in a throwaway only with the hardened invocation, and only in a throwaway no untrusted process has written (review-respond's clean checkout for confirm, a second, fresh throwaway created with `--source remote`, never from the agent-writable local clone, and pushed to the clone fetch URL (D46) from `wtctl locate --json` (`fetch_url`) with the caller's own credentials: [Clean checkout for confirm](interface.md#clean-checkout-for-confirm)); no trusted process runs anything in a throwaway an agent has touched. `extract` writes only listed regular files into the clean checkout, and no untrusted process ever ran in it. A remote-source throwaway's fetch is its only network command; a local-source throwaway is built from a pack with no network command and no fetch from the clone (D54); the checkout runs with protocols `none` and `GIT_NO_LAZY_FETCH=1` (D9). A throwaway never fetches from wtctl's mirror (D50), whose trees are partial. | Spike A4/A5: a global `init.templateDir` installs hooks and config; global smudge filters run on checkout; a filter planted in the throwaway's config runs on a later trusted `git status`. Spike A2: `FETCH_HEAD` and the reflog leak the source path and the user's identity. A second throwaway gives review-respond a clean checkout at the PR head without touching the user's clone, branch rules, bootstrap or baseline, and with filters off it matches what the agent saw (user decision, 2026-10-30). Spike E1f: a trusted agent can substitute objects in the local clone's store under their real shas, so a clean checkout fetched from it could show the user a diff against substituted base content; fetching from the remote avoids that, and a throwaway's own `fetch_url` may be the local clone's path, which is no push target (review pass 2). |
| D14 | Ignored files block removal as `dirty` unless bootstrap-created or matched by `remove.disposable` (common caches and build output by default); any nested git repository always blocks, found by a no-follow walk of the whole tree (ignored, disposable and bootstrap-created directories included) that stops descending at a found `.git` and never crosses a mount point (a mount point anywhere inside fails the check with detail `mount_point`, D55); `.git` entries that exist inside bootstrap-created directories right after bootstrap are recorded (`bootstrap_nested`) and exempt, every other one blocks; beyond `remove.nested_scan_limit` entries (default 2,000,000) the check fails (`incomplete`); an initialized submodule fails with detail `submodule` (D47) ([Content checks](interface.md#content-checks)). | Keeps the architecture's intent (unexpected ignored files are protected) while letting automated teardown work after agents ran tests. Spike B5: `git worktree remove` silently deletes ignored content, including nested repositories and their history, wherever they are. A bounded scan fails closed rather than passing. A single `node_modules` of an ordinary JS or TS project can exceed 100,000 entries, so the first default (100,000) would have refused most automated teardowns; package managers can install git dependencies as nested repositories, which bootstrap's own record covers (review pass 2). |
| D15 | A failed pre-removal mirror refresh (D50) exits 12 (`fetch_failed`, or `auth_required` when the remote asked for credentials); a human `--force` overrides either and proceeds with a warning. The outcome is classified by exit status and stderr, and an exit 0 with an `error:` line counts as `fetch_failed` (`prune_incomplete`) ([Remove order](interface.md#remove-order) step 5). The same classification applies to every mirror refresh (create, `status`, reconcile). | An operational failure, not a judgment about content; stale refs could make work look pushed (spike B8). Spike F4: exit 1 is ref-lock contention, exit 128 a transport failure whose stderr separates authentication; a `--prune` blocked by `packed-refs.lock` exits 0 and leaves a stale ref that could make deleted remote work look pushed. Spike G3: a refresh exits 0 on a no-op and when every ref is pruned, and 128 when the remote is unreachable. |
| D16 | Superseded by D50 (safety check, user decision R-11). It fetched the recorded URL into a namespace inside the user's clone for the objects and took the tips from a separate remote listing; `refs/remotes/` was never consulted, which D50 keeps. | Spike C4g: an `insteadOf` pointing at an agent-owned repository prunes every `origin/*` ref; forged `refs/remotes/` refs could make unpushed work look pushed. Spike F4e: even a tool-owned namespace can keep a stale ref after a fetch that exits 0. The safety check (SAFE-2, SAFE-3, SAFE-4) then showed that any network fetch run in the agent-writable clone honors repository config wtctl cannot fully neutralize. |
| D17 | `remove` deletes the worktree's branch only if wtctl created it and its tip is pushed (the mirror check of D50 with content-verified ancestry, D31) or equals `--merged-head`, with a compare-and-swap delete (never the zero sha); kept on a forced unpushed removal. | Lossless by construction; keeps clones tidy. Spike B9: `branch -d` refuses squash-merged branches; `update-ref -d <ref> 0…0` deletes without checking. Spike E1: the compare-and-swap is unaffected by replace refs and grafts, but a forged ancestry would otherwise delete an unpushed branch. |
| D18 | Minimum git 2.34 (Ubuntu 22.04); newline-separated porcelain parsing; paths with newlines refused; per-filter blanking instead of `--attr-source`. | The user's machines run 22.04 or newer; Apple git is 2.39. Spike B: `worktree list -z` needs 2.36, `--attr-source` is newer. |
| D19 | Ids `wt-` + 8 base32 characters; addressing by id prefix or absolute path; label selectors only on `list` and `prune`; a derived name is deduplicated against live records and against existing paths on disk ([Identifiers](interface.md#identifiers)). | Matches claude-session (`cs-`) and termctl (`tc-`); a label typo can never remove the wrong worktree. A leftover directory at a derived path (a forgotten worktree, an abandoned create) would otherwise make every retry exit `path_exists` (review pass 2). |
| D20 | Hooks: `pre-create`, `post-create`, `pre-remove`, `post-remove`, `post-reconcile`, `post-baseline-accept` ([Hooks](interface.md#hooks)). | The meaningful, vetoable steps; bootstrap is part of create and reported by `post-create`. |
| D21 | Audited: worktree removals, branch deletions, `baseline accept`, `adopt` and reconcile's admin-entry deletions; everything else is logged ([Audit and log](interface.md#audit-and-log)). | Removals are where "where did my work go?" gets asked; routine creates are not audit material. |
| D22 | `remove` refuses `in_use` when a process of the user has its cwd or an open file inside, matched by `(st_dev, st_ino)` of every directory in the target (no-follow walk that never crosses a mount point, D55, bounded by `remove.nested_scan_limit`; cwds are directories) for cwds, and by path prefix for cwds and open files; wtctl's own process, its children and its ancestor chain are excluded (excluded ancestors with a cwd inside are listed in `warnings`); never overridable; wtctl never signals ([In-use detection](interface.md#in-use-detection)). | Catches the common accident of deleting under a running dev server, shell or session; the same spirit as "nothing overrides `live`". Spike D1: a stdlib `/proc` scan takes about 20 ms. Spike E3: a sandbox that bind-mounts the directory at another path hides it from path matching; device and inode still match. Claude Code's sandbox binds the same path, so open files are matched by path prefix; collecting only directory inodes keeps the walk cheap in large trees (review pass 2). Safety re-check SAFE2-1: an agent's FUSE mount can be infinitely deep, so an unbounded walk hung wtctl under the lease; the walk now shares the `nested_repos` limit and stops at mount points. Excluding the ancestor chain lets a caller whose shell or supervisor sits in the worktree run the removal. |
| D23 | No TUI in v1. | A plumbing primitive; every action is one command; the awkit dashboard shows worktrees in its chains. |
| D24 | `adopt` records worktrees wtctl did not create (`owned: false`); holders are allowed on owned and adopted records: `create --holder <h>` and `adopt --holder <h>` add one (an `adopt` of an already recorded path only adds the given holder, under that record's per-record lease and only to an `active` record, D26). `remove` refuses `held` (exit 20, `details.holders`) while the record has a holder other than the one passed with `remove --holder <h>`; a human `--force` overrides `held`. `forget --holder <h>` removes `h` (a non-holder is a no-op with the warning `not_a_holder`) and forgets the record only when this call removed the last holder of an adopted record; owned records are never forgotten this way. A plain `forget` is human-only (D35); removing an adopted worktree is human-only; the main worktree is never removed ([`adopt`](interface.md#adopt), [`forget`](interface.md#forget), [`remove`](interface.md#remove)). | agent-spawn's `--worktree <path>` needs a baseline there without wtctl ever deleting a directory it did not create on automation's behalf. Holders are reference counts: one agent's teardown cannot drop a record another agent, or an owned worktree's creator, still relies on (user decision, 2026-10-30). Review pass 2: a creator's teardown could otherwise delete a worktree a parked agent still holds, and a `forget --holder` of a non-holder could forget a record someone else adopted. |
| D25 | `extract` owns the safe-extraction rules review-respond's confirm uses ([Extraction rules](interface.md#extraction-rules)). File modes are never copied (architecture §20: an existing file keeps its mode, a new one gets 0644); every per-path error and a write failure (`io_error`) have typed values. | The filesystem-safety code lives once, next to the fd-based removal it shares, with one adversarial test suite (spike D4). |
| D26 | State in SQLite (`state.db`, WAL); global, per-repo (clone creation, D42), per-clone and per-record leases ([Locking](interface.md#audit-and-log)); `adopt` takes the per-clone lease, and also the per-record lease when the path is already recorded (it then acts only on an `active` record); read-only commands (`status`, `baseline check`, `show`, `list`) take no record lease, and `status`'s fetch takes the per-clone lease. A lease is waited for up to `lease_wait` (default `10m`) before `busy`. Every state transition is a compare-and-set on `state`, and a lost race exits 12 `busy` (or 10 if the record became a tombstone). | Records, baselines and snapshots must live outside what agents routinely write (git config and worktree content are agent-writable). They are not tamper-proof: `state.db`, the mirrors (D50) and wtctl's roots are writable by any unsandboxed process of the user, trusted agents included, so wtctl's guarantees against trusted agents cover their git-config and worktree-content tampering, not direct edits of wtctl's own state, which would be deliberate sabotage by a trusted agent ([Residual risks](interface.md#residual-risks); safety check SAFE-10); concurrent cron and agent-spawn calls need transactions; without compare-and-set, a concurrent `forget` and `remove` could corrupt a record's state. Create holds the per-clone lease through the fetch, the `pre-create` hooks and `worktree add` (minutes with LFS), and `remove` holds the per-record lease through its prompt, so the first 30-second wait made a second launch on the same clone fail; read-only commands blocking behind a prompt would stall agent-spawn's `show` and pre-resume check (review pass 2). An `adopt` adding a holder without the record lease could race a `forget` or `remove` and attach a holder to a tombstone (review pass 3). |
| D27 | `create.allow_filters` (empty by default): allowed filter drivers take their definition from the user's global config, only when it defines `process`. When an allowed driver is honored, `create` refuses (exit 12 `unsafe_repo_config`) if the repo config or the checkout commit's `.lfsconfig` holds a git-lfs key that runs a program or redirects transfers ([Hardened git](interface.md#hardened-git)). | Isolated global config would otherwise leave git-lfs files as pointers (spike D2a). Spike D2c: a repository-planted `process` beats a trusted `smudge`, and an empty `process` disables `smudge`. git-lfs reads repository config itself, so a trusted agent could plant a custom transfer agent that the next `create` would run unsandboxed (key list unverified, spike E2). |
| D28 | `status` runs the removal checks read-only and takes `--merged-head` and `--holder` (as `remove` does), and `remove --dry-run` is the same command (D43). `would_remove` is `true`, `false` or `null` (could not determine, e.g. the fetch or authentication failed; the checks that need the fetch are then `skipped`, never `fail`). A removal only a human may perform is reported as `human_required: true`, not as a `reason`. | Callers (agent-spawn `show`, the dashboard) can ask "would removal be refused, and why?" without attempting it. A failed fetch is not a refusal, and `not_owned` as a reason contradicted `remove`, which exits 13 for an adopted record without a human (review pass 2). |
| D29 | The unpushed-branches check uses the worktree's own HEAD reflog since create (or adopt), not a snapshot of `refs/heads`. The start is recorded as the create or adopt timestamp plus the starting entry's new sha, and an entry is attributed to the worktree when its timestamp is at or after the recorded start or when it comes after the recorded start sha's entry in the file (positional, when that entry is still present); `reflog_unavailable` when neither anchor is usable; a missing or unreadable reflog, or one with no entry at or before the start (emptied, or expired by gc after `gc.reflogExpire`, 90 days by default), fails the check (`reflog_unavailable`; a human `--force` overrides, so worktrees older than that expiry need a human for this check), with no snapshot fallback. Signed off by the user (2026-10-30), replacing the earlier approved `refs/heads` snapshot. | `refs/heads` is shared by the clone: the user's own commits elsewhere would make every removal look unpushed. The worktree's HEAD reflog holds exactly the commits made in it (spike B7 found side branches; this scopes them). Failing on an unusable reflog keeps the check safe when `core.logAllRefUpdates=false` or `reflog expire` empties it. Spike F2: `init` and `clone` write `core.logallrefupdates = true` into the repo config, so a global `false` has no effect, while a repo-level `false` stops new entries and is a baseline change; `reflog expire --expire=now --all` empties the files (also a linked worktree's) and keeps them. A recorded entry count (the first design) misattributed entries once gc expired old ones in a long-lived worktree; a timestamp start does not (review pass 2). An agent that empties and refills the reflog can still hide a side branch: the check is defense in depth ([Residual risks](interface.md#residual-risks)). Spike V1: `GIT_COMMITTER_DATE` backdates the reflog entry, so a timestamp alone missed a backdated commit; the positional anchor catches it while the start entry is present, and a trusted agent that backdates commits once that entry is gone remains a residual risk (review pass 3). |
| D30 | One visible root for everything wtctl creates on disk: config `root` (default `~/wtctl`) with `worktree_root` = `{root}/worktrees`, `throwaway_root` = `{root}/throwaway` (0700, owner checked with `lstat`) and `clone_root` = `{root}/clones`, each overridable; a configured root that fails claude-session's unsafe-write-target rules exits 2 (wtctl implements the subset relevant to directories it creates: `$HOME` and its ancestors, hidden home directories, XDG homes, `PATH` directories; claude-session's own launch check stays authoritative); state stays under XDG state ([Locations](interface.md#locations)). | claude-session refuses an isolated run's cwd inside `$HOME/.<name>` or an XDG home, so throwaways under the state dir broke every respond round, and worktrees under the data dir broke any isolated run in a worktree. A test compares the defaults with claude-session's rule list (user decision, 2026-10-30). |

| Module | Responsibility |
|---|---|
| `cli` | argparse surface, global flags, output selection, exit codes |

| `mirror` | the per-clone mirror (D50): create and config, refresh and outcome classification, default branch, pushed check, base-commit transfer into the clone (pack built in the mirror and indexed in wtctl's private temp dir, D54) |

| `remove` | removal orders (deletion through `fsafe`, never `git worktree remove`), branch deletion |

Data flow for `remove`: `cli` → `config` → `state` (resolve, leases) → `checks` (integrity via `fsafe`, baseline via `baseline`, in-use via `gateway`) → `mirror` (refresh) → `hardgit` (status, `ls-files`) → `checks` (content, pushed check in the mirror) → `cli` (confirmation) → `hooks` → `remove` (re-check, fd-based delete of the tree and the admin entry via `fsafe`, verify, branch) → `state` → `audit` → `hooks` → `output`.

**Data model** (`state.db`, schema version 1):

- `records(id PK, object_type, owned, state, repo, clone_path, common_dir, common_id, admin_dir, base_dir, root_id, path, dir_id, name, branch, created_branch, base, base_sha, head_at_create, ref, source, depth, fetch_url, remote, reflog_start_ts, reflog_start_sha, baseline_digest, bootstrap_state, missing_since, missing_seen, created, updated, removed_at, last_error)`; partial unique indexes on `(repo, name)` for live worktrees and on `path` for live records (adopt of a recorded path returns that record). `state` is one of `creating`, `active`, `unlinked`, `missing`, `clone_missing`, `partial` (live) and `gone`, `removed`, `forgotten` (tombstones) ([Records](interface.md#records)). `path` is a realpath (for `adopt`, the realpath of the given path); `admin_dir` is the admin entry from `rev-parse --git-dir` (null for a main worktree or a throwaway); `common_id`, `dir_id` and `root_id` are recorded anchor identities, `(st_dev, st_ino)` stored as `<dev>:<ino>` (D55): `common_id` is the clone's common dir (worktrees; copied from `clones.common_id`), `dir_id` the worktree directory (recorded at create, adopt and crash reclaim) or the throwaway directory (recorded right after its `mkdirat`), checked before deletion and pointer rewrites (D51, D52), null only while `creating` and in tombstones of records that never left it; `root_id` is the throwaway root (throwaways), copied from the root's `anchors` row; only a human `baseline accept` changes them (D56); `base_dir` is the realpath of the worktree or throwaway root the record's path lives under, resolved at create (D1, D30; the config keys stay `root`, `worktree_root` and `throwaway_root`; null for adopted records); `reflog_start_ts` and `reflog_start_sha` are the create or adopt timestamp and the starting entry's new sha (D29); a `creating` throwaway may have `source` set to the requested mode (`auto` allowed) and null ref fields not yet known (D40); `base_sha` is the resolved `--base`; `missing_since` and `missing_seen` drive the reconcile grace (D32); `bootstrap_state` is `none`, `ok`, `failed` or `interrupted` (a create reclaimed after a crash, D40).
- `holders(record_id, holder)`, unique per pair; allowed on owned and adopted worktree records (D24).
- `labels(record_id, key, value)`, unique per triple; rendered as sorted `key=value` strings (D38).
- `stash_ids(record_id, oid)`: the full set of stash entry ids at create or adopt ([Content checks](interface.md#content-checks), `stash`).
- `baseline_items(record_id, path, key, kind, class, digest, anchor_id)`; `key` is the config key (`section[.subsection].key`) for config items, else null; `class` is `git` or `claude` (D10); `anchor_id` is the recorded `(st_dev, st_ino)` of a `core.hooksPath` directory outside the common dir (its own anchor, D55), else null.
- `bootstrap_paths(record_id, path, kind, digest)` (`kind`: untracked file, exempted by exact path and unchanged digest, or ignored directory, exempted by prefix), `bootstrap_nested(record_id, path)` (the `.git` entries inside bootstrap-created directories right after bootstrap, exempt from `nested_repos`, D14) and `bootstrap_runs(record_id, run, step, argv_json, exit, duration_ms, output_tail, started)`.
- `clones(repo PK, path, common_dir, common_id, source, fetch_url, mirror_path, verified_at, default_branch)`; `common_id` is the common dir's recorded identity, set when the repo's clone is first stored or when wtctl itself clones it, and otherwise changed only by a human `baseline accept` or `clone` (D55, D56); `fetch_url` is the clone fetch URL, re-verified on every resolution (D46); `mirror_path` is the clone's mirror (D50), named by a hash of the realpath of the clone's common dir, so it is unique per clone; `default_branch` is read from the mirror's `HEAD` symref.
- `anchors(path PK, dev_ino, recorded_at)`: the recorded identity of each worktree root and throwaway root (realpath), recorded when wtctl creates the root with `mkdir`, or at first use of a root that already exists (trust on first use); changed only by a human `baseline accept` (worktree roots); a root no record can re-accept is re-recorded only after a human removes it and wtctl creates it again (D56).
- `leases(name PK, pid, start_time, expires)`.
- `schema_version(version)`.

**Concurrency.** Leases as in [Audit and log](interface.md#audit-and-log) (Locking). A lease's expiry is 10 minutes and is renewed while held, including during prompts, hooks, bootstrap steps and fetches; a holder that died (PID plus start time no longer match) is taken over immediately; a live holder is waited for up to `lease_wait` (default `10m`), then the command exits 12 `busy` and the caller may retry. `remove` takes the per-clone lease only for the fetch and for the final re-check and deletion; `create` releases it before bootstrap and holds the per-record lease from the record write through the final compare-and-set after bootstrap. Reconcile and prune take a record's per-record lease without waiting before changing it and skip the record when a live process holds it (D40). Read-only commands take no record lease (D26). Every state transition is an `UPDATE … WHERE state = <expected>`; a lost race exits 12 `busy`, or 10 when the record became a tombstone (D26). Lease contention (`busy`, exit 12, transient) is distinct from a target in use (`in_use`, exit 20, a refusal).

**Error handling.** Expected failures map to exit 12 with an `error.code`, refusals to exit 20 with a `reason`, both from one table in `cli`; every git failure carries git's stderr (cut to 4096 bytes) in `details`, never into `message`. Unexpected exceptions exit 1 with `internal`.

## Mirror implementation notes

The recipe for D50 and D54, from spikes G and H (git 2.34.1). The security properties are normative in [Mirror](interface.md#mirror); the commands below are the implementation recipe, and each becomes a regression test. `W` is the hardened invocation (D9; protocols `none` and `GIT_NO_LAZY_FETCH=1` unless stated otherwise), `M` the mirror's absolute path (`W M` = `W --git-dir=M`).

**Create** (once per clone, at `M` = `${XDG_STATE_HOME}/wtctl/mirrors/<key>.git`, D50; the config is rewritten whenever the clone fetch URL changes):

```text
git init --bare --template= M          # clean environment, mode 0700
git --git-dir=M config core.repositoryformatversion 1
git --git-dir=M config extensions.partialClone origin
git --git-dir=M config remote.origin.url <clone fetch URL>
git --git-dir=M config remote.origin.promisor true
git --git-dir=M config remote.origin.partialclonefilter tree:0
git --git-dir=M config gc.auto 0
git --git-dir=M config core.logAllRefUpdates false
```

wtctl writes the promisor config itself so it is deterministic (spike G1: git would otherwise write `[remote "<url>"]` keys on the first filtered fetch by URL). A GitLab HTTPS URL without `.git` is normalized to end in `.git`: with redirects off (D9), gitlab.com answers the bare form with a 301 that fails the fetch (spike G1).

**Refresh** (protocols = the URL's scheme; credentials as in [Credentials](interface.md#credentials)):

```text
W M fetch --no-tags --prune --filter=tree:0 origin '+refs/heads/*:refs/heads/*'
```

Exit 0 on success, including a no-op and every ref pruned; 128 when the remote is unreachable; the outcome is classified as in D15, including an `error:` line on exit 0. The default branch: `W M ls-remote --symref <url> HEAD` (in the mirror, so only its wtctl-owned config applies; never with no repository, SAFE2-4), then `W M symbolic-ref HEAD refs/heads/<branch>`.

**Pushed check** (protocols `none`, `GIT_NO_LAZY_FETCH=1`):

```text
echo C | W M cat-file --batch-check    # "<C> missing" → unpushed
W M merge-base --is-ancestor C <tip>   # per refs/heads tip: 0 pushed, 1 not, 128 missing → unpushed
                                       # then the content re-hash of a parent path (D31)
```

Without blocked protocols, a lookup of a missing commit in the promisor mirror triggers a lazy network fetch (spike G2). Never `rev-parse <commit>^{tree}` in the mirror: it needs the tree object.

**Base commit into the user's clone** (create, when the base or a remote-only branch's tip is not in the clone; D54, spike H1(b)). No git command runs in the clone with a protocol other than `none`, and no git command at all writes the clone during the install. `C` is the clone's common git dir, `P` a fresh per-call 0700 directory under `${XDG_STATE_HOME}/wtctl/tmp/`; commands outside a repository run with cwd `P` and `GIT_CEILING_DIRECTORIES` set to `P`'s parent (git ignores a ceiling equal to the cwd itself, so the parent is the one that stops discovery).

1. `PRESENT`: the clone's ref tips (`W --git-dir=C for-each-ref --format='%(objectname)'`, protocols `none`) that `W M cat-file --batch-check` finds as commits in the mirror. The data is untrusted: it only shrinks the pack, and a planted ref or a deleted object makes this create fail cleanly at step 7.
2. The commits and root trees needed, with no network: `W M rev-list BASE --not $PRESENT` into `P/need`, then `W M rev-list --no-walk=unsorted --format=%T --no-commit-header` over `P/need` and `PRESENT` (protocols `none`). The `PRESENT` root trees are needed too, or `pack-objects` cannot compute the exclusion. Use `rev-list`, not `log`: `log --format=%T` lazy-fetches in a treeless mirror (spike H surprise 5).
3. One network round trip for full trees and blobs, with noop negotiation (mandatory: with default negotiation github.com omitted objects and the fetch failed, spike G4): `W M -c fetch.negotiationAlgorithm=noop fetch -q --no-tags --no-write-fetch-head --no-filter origin <T...>`. This is the only step with a protocol other than `none`, and it runs in wtctl's mirror. Fetching the commit sha with `--no-filter` is a silent no-op because the commit is already local, and `--refetch` does not exist in 2.34, hence tree wants.
4. A **non-thin** pack in the mirror (protocols `none`): `BASE`, `--not` and `PRESENT` on stdin to `W M pack-objects --revs --stdout -q > P/x.pack`; exit status 0 required.
5. Index it **outside any repository** (cwd `P`, ceiling as above): `W index-pack --fsck-objects -o P/x.idx P/x.pack`, which prints the pack checksum `H`; exit status 0 required. No repository's config is read.
6. Install with plain fd-based writes: `objects/pack/` is opened component by component with `O_NOFOLLOW|O_DIRECTORY` from the recorded common dir (mount check as in D55); `pack-H.pack` is written first, then `pack-H.idx` (git finds packs through the `.idx`), each under a temporary name with mode 0444, then installed with a no-replace link (`linkat` and then `unlinkat` of the temporary name, or `renameat2` with `RENAME_NOREPLACE`); an existing file of the same name is left as it is. A plain `renameat` would overwrite it. A chain directory on another device or mount than the common dir fails the create (`create_failed`).
7. Verify: `W --git-dir=C rev-list --objects --missing=print BASE` (protocols `none`) must print no line starting with `?`; otherwise `create_failed` (the clone lacks an object it claimed through its tips).
8. `worktree add` in the clone (protocols `none`, `GIT_NO_LAZY_FETCH=1`).

Pitfalls (spike H):

- **Non-thin only.** A thin pack cannot be indexed outside a repository ("pack has N unresolved deltas"), and `index-pack --fix-thin` in the clone lazy-fetches the new objects from a planted promisor even when nothing was tampered with. Never run `--fix-thin` in the clone. The non-thin overhead is bounded by the range's own objects (12.7 KB against 5.9 KB thin in the spike).
- **`--fsck-objects`, not `--strict`, outside a repository.** `index-pack --strict` with no repository segfaults on git 2.34.1 (exit 139); `--fsck-objects` gives an identical index.
- **Ceiling directories.** Every command wtctl runs outside a repository (`index-pack` here, `init`, `clone`) sets `GIT_CEILING_DIRECTORIES` to the parent of its private cwd, so git never discovers an ancestor repository (SAFE2-4).
- For SHA-256 repositories `index-pack` would need `--object-format`; they are unsupported in v1 (D48).

**Throwaway from the local clone** (`--source local`, or `auto` when the clone has the commit; D54, spike H2). Every command against the clone runs with protocols `none`; the throwaway `T` is fresh and wtctl-owned.

```text
W --git-dir=C rev-list --objects --no-walk SHA > P/list        # depth 1; exit status must be 0
W --git-dir=C rev-list --objects SHA > P/list                  # full history (default); exit status must be 0
W --git-dir=C pack-objects --stdout -q < P/list > P/t.pack     # exit status must be 0
W init -q --template= T                                        # cwd P, ceiling as above
echo SHA > T/.git/shallow                                      # depth 1 only; before index-pack
W --git-dir=T/.git index-pack --stdin --strict < P/t.pack
W --git-dir=T/.git update-ref --no-deref HEAD SHA
W --git-dir=T/.git --work-tree=T read-tree -u --reset HEAD
```

Pitfalls:

- **Truncated pack.** With a missing object, `rev-list` exits 128 part way through while a piped `pack-objects` exits 0 with a partial pack. The list goes to a file and both exit statuses are checked; never a shell pipe.
- The shallow file must precede `index-pack --strict` for depth 1, or `--strict` fails on the missing parent. `--strict` belongs here: it fscks agent-supplied objects (malformed trees, `.gitmodules`) in a repository wtctl owns, so no clone config is read.
- No depth other than 1 or the full history: `pack-objects` has no depth primitive (D12).

**Why packs** (spike H, safety re-check SAFE2-2): any git command run against the agent-writable clone with `file` allowed runs a planted promisor's `uploadpack` on a missing object, on every build without `GIT_NO_LAZY_FETCH`; protocols `none` blocks it on every command tested (spike H3), and building, indexing and installing packs needs no other protocol. The earlier clone-side fetch from the mirror (per-call symlink, `--upload-pack`, `--refmap=`, `-c core.alternateRefsCommand=true`) and the throwaway's fetch from the clone path are gone; a `pack-objects` run in the clone with protocols `none` fails cleanly on a missing object.

**Cost.** The first refresh is a commits-only fetch, about 25–30% of a full fetch (spike G1: 1.8 MB against 5.8 MB for a mid-sized Python project). A base transfer from a clone that shares no tips with the mirror costs up to a full history of trees; with shared tips it costs about as much as an incremental unfiltered fetch (spike G4b: 33–48 tree wants, 0.35 s), plus a local non-thin pack of the range (spike H1: 80 objects, 12.7 KB). A full, unfiltered mirror would drop steps 1–3 at about three times the disk; the treeless one is the v1 choice. Pack-based transfer on a large monorepo is still to verify.

The safety check (an attacker in the session) used git 2.34.1 on Linux 5.15 with the full hardened wrapper and local HTTP servers. Spike H (pack-based transfer and mount points, D54, D55) and the safety re-checks (SAFE2, SAFE3) used git 2.34.1 (Ubuntu build with the backport) on Linux 5.15 with the full hardened wrapper, no network and one local HTTP server; they emulated upstream git without the backport by running every hardened call with `GIT_NO_LAZY_FETCH=0`, and used an unprivileged FUSE passthrough (`fusermount3`) and `unshare -Urm` for mounts. ## Dependencies

- Runtime: Python 3.12+, `pyyaml` (config), `pydantic` (config validation); git 2.34+; on macOS, `lsof` (in-use detection, optional).
- No awkit tool dependencies. git is called directly (binding A to a third-party CLI); no git library (`GitPython`, `pygit2`) is used, because the hardened invocation must control git's environment and arguments exactly.

## Testing

- Real git in temporary directories for unit and integration tests (fast and deterministic, no network); the process scanner and the clock are faked through `gateway`.
- The hardened-git vector suite (spikes C and E: execution vectors, forged ancestry including object substitution, ssh batch mode, header scoping) and the lifecycle facts (spike B) run as ordinary tests: every planted vector must leave no marker, and every forged ancestry must report unpushed.
- The default locations (D30) are checked against a copy of claude-session's unsafe-write-target rule list.
- In-use detection is tested with a process whose cwd is reached through a bind mount in a user namespace (spike E3), where unprivileged user namespaces are available.
- An adversarial `fsafe` suite: symlinked components, hard links, `.GIT`, `..`, FIFOs, directories swapped for symlinks between validation and write, and a background loop exchanging a directory and a symlink during worktree deletion and ancestor swaps before it (SAFE-1, SAFE-8, D51); pointer rewrites never write outside the recorded path and admin entry, including when the admin entry was replaced by a symlink (D52, SAFE2-6); an unprivileged FUSE mount at a disposable path inside a worktree, an admin entry and a throwaway, and one mounted *on* an admin entry, on `<common>/worktrees`, on `<common>/hooks` and on a throwaway directory (refused before anything is deleted, SAFE3-1, SAFE3-2), (skipped where `/dev/fuse` or `fusermount3` is unavailable) and a same-filesystem bind mount in a user namespace (skipped where unprivileged user namespaces are unavailable) are never descended into by any walk, fail `dirty` with detail `mount_point`, and leave a throwaway `partial` with the mount listed (D55, SAFE2-1, spike H5).
- Golden `--json` files validated against `schemas/`.
- A large `node_modules` fixture (generated, hundreds of thousands of entries, with a git dependency installed by bootstrap) for `nested_repos`, the `bootstrap_nested` exemption and in-use detection (D14, D22).
- The baseline against a recorded sandboxed session's traces (D41): no change in either class.
- A mirror vector suite (D50, spike G5, SAFE-2/3/4): with the clone full of planted config (promisor remote, `remote.<url|path|file-url>.*`, equal-length `insteadOf`, `core.alternateRefsCommand`, `http.*`), refresh, pushed check, base transfer and `worktree add` leave no marker and move no ref, and a planted promisor never runs during any non-network command. Every row also runs with `GIT_NO_LAZY_FETCH=0` to emulate upstream git without the backport (SAFE2-2, spike H): the pack-based base transfer and the local-source throwaway leave no marker, an object deleted from the clone makes `create` fail with `create_failed` at the `--missing=print` check, a `rev-list` failure never yields an installed or indexed truncated pack, and no git command against the clone runs with a protocol other than `none` (asserted on the gateway's recorded invocations) (D54).
- Hardened-git regressions from the safety re-check: a `tracked` edit hidden by forged index stat data (and a forged untracked cache) fails the check through the private index (D53, SAFE2-3); `ls-remote --symref` and every command run outside a repository ignore a planted ancestor `.git` with `http.proxy` and `insteadOf` (D50, SAFE2-4); two clones of one repo, case-distinct repo ids and a repo id ending in `-2` get distinct mirrors (D50, SAFE2-5); every diff-family command passes `--no-ext-diff` and works under `-c diff.external=` (D9, spike H surprise 6); `--source local` with `--depth` other than 0 or 1 exits 2 and `auto` then prefers `remote` (D12).
- `live` tests (deselected by default, never in CI): remote fetch-by-sha on github.com and gitlab.com, mirror refresh and base transfer on github.com and gitlab.com (noop negotiation, GitLab `.git` normalization), HTTPS token headers, real git-lfs.
